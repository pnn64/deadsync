# Lua 5.1 native chunk execution validation

Verified native chunks now translate into the existing register interpreter.
All 38 native opcodes have translation paths; no C execution fallback or second
runtime is added. Constants, tables, functions, environments, cells, coroutines,
errors, native calls and the collector use the same VM as source programs.
The generated IR is structurally verified before a `Program` is returned.

The bridge expands register-or-constant operands, fixes native jumps, folds
test/embedded-jump dispatch and skips closure-binding words/extended SETLIST
payloads on their ordinary execution paths. Per-site bindings allow different
closures to instantiate the same child prototype with different captures.
Root native upvalues receive independent closed nil cells. Old vararg `arg`
tables and open arguments/results use the existing frame machinery.

Imported debug metadata preserves source inheritance and distinct child names,
local scopes, upvalue names, active lines and native dispatch hook counts.
Stripped functions report line zero; translation scratch slots do not appear as
debug locals. Range concatenation preserves native numeric coercion and batching
order, resumes metamethods without recursive interpreter entry and retains the
correct parent debug window. Generic-for calls retain native yield barriers and
contribute to native call-depth limits, including inside coroutines. Collector
maps exclude dead scratch slots and duplicate caller argument copies while
callees own their values; a weak-value regression covers overwritten arguments.

All **380 tests** pass: 345 integration groups, 34 unit groups and one doc example.
Four new unit groups cover:

| Area | Evidence |
| --- | --- |
| Instruction execution | Official chunks with arithmetic, constants, methods, table access, loops, captured scopes, tail calls, old/modern varargs, open results, metatables, coroutines, yield/depth restrictions, weak collection and a 25,551-element extended SETLIST constructor. |
| Native debugging/hooks | Exact scalar and byte observations for names, locals, source/line data and line/count/call/return hooks, including stripped chunks and callback-visible concatenation slots. |
| Bindings/source metadata | One child instantiated at two distinct capture sites, root cells surviving collection/reuse, and distinct nested source names. Only these deliberately valid mutations execute in C. |
| Generated programs | 256 deterministic valid programs with register/constant operands, nested calls, comparisons, logical expressions and loops, alternating full and stripped metadata. |

An additional source-compilation regression uses the same iterator-call opcode
to enforce native yield/depth boundaries for ordinary generic-for loops. It
checks direct yielding and recursive iterator overflow on the main thread and
inside a coroutine.

Existing structural decoder tests still cover every stream split point,
truncations, header mismatches, untrusted lengths/depths, all instruction-bit
mutations and generated bytes. Invalid mutated chunks are never executed by
the C oracle. Translation additionally rejects invalid local metadata,
overflowing SETLIST starts and invalid generated IR; this remains stricter than
some C-accepted adversarial chunks and is not a general safety proof for C.

All [132 process probes](2026-10-25-rust-lua-chunk-exec-process.json) match complete exit status,
stdout/stderr bytes and recorded file bytes across the official C engine, Rust
runner and CLI. Three additions generate a fixed native fixture with the
development oracle, then execute it through `loadstring`, one-to-seven-byte
readers with collection, trailing data, named binary files and executable
headers. CRLF/control-Z bytes are retained through binary reopening. No Rust
`string.dump` implementation or synthetic successful dump is used.

The [official suite report](2026-10-25-rust-lua-chunk-exec-suite.json) keeps sixteen unchanged,
checksum-pinned files, `_U=true`, 100-million-instruction budgets and 60-second
per-file deadlines. Rust passes fourteen; the reference fifteen. Rust still
stops at `calls.lua:243` because `string.dump` is missing. Both engines fail
`files.lua:59`, the Windows open-input rename assertion. The suite command
therefore remains unsuccessful. These isolated probes are not complete
`all.lua` or internal C API coverage.

Formatting, strict crate Clippy with dependencies excluded, whitespace checks
and the normal/build dependency tree pass. The latter contains only this crate;
no Cargo dependency or production unsafe code is added. The development-only
test oracle enables C debug access in one explicitly scoped unsafe block.
Production DeadSync consumers remain on the legacy engine.

```sh
cargo test -p deadlib-lua
cargo fmt -p deadlib-lua --check
cargo clippy -p deadlib-lua --all-targets --no-deps -- -D warnings
cargo tree -p deadlib-lua --edges normal,build
python scripts/check_rust_lua_process.py --output docs/testing/2026-10-25-rust-lua-chunk-exec-process.json

```

All report hashes match the final source tree. [Measurements](../performance/2026-10-25-rust-lua-chunk-exec.md)
retain two runs over 57 runtime and twenty-two frontend workloads, including
three native-chunk import/execution fixtures. The validated ABI remains Windows
x86-64 MSVC, little endian, size_t 8, int/instruction 4 and binary64 8. Other
platform execution remains unverified. Complete binary diagnostic/provenance,
debug mutation, collector and resource equivalence require broader coverage.
Dump emission is the next binary milestone; persistent caching, native modules,
later dialects, host APIs, optional JIT and integrations remain unfinished.
