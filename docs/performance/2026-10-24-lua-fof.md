# Compile byte-keyed input state and restore interactive FoF loading

Baseline: `8245d1d5ba8f7653ecbb0711a9570f529f03e4ae` (0.5.2364). Result: 0.5.2365. Executables were measured at 0.5.2364; the final version bump and Lua 5.1 example feature gate are metadata changes. Measurements use release builds, locked dependencies, LTO disabled, two build jobs and logical CPU 2 affinity. Timing runs serially outside compilation. The adjacent JSON preserves raw measurements, source/binary receipts, caller-supplied input tapes and focused validation results.

## Retained mechanisms

1. `deadlib-lua::program` owns raw byte-keyed Boolean/nil tables. The compiler lowers typed reads and writes into native state, preserving present false entries, nil deletion, arbitrary byte keys and distinct table identities. Independent Machines own independent mutable state; callbacks in a Group share declared identities. The schema and immutable initial state outlive the loading VM through ordinary Rust ownership.

2. Immutable dense arrays can refer to those tables, including aliases. Abstract integer ranges prove that runtime-selected indices remain in bounds; they do not replace runtime numeric values. This compiles the original, unmodified `InputSystem.handle_input` from Fof Guys: each player's first press/repeat sets a held button and release removes it. Player, event kind and button remain runtime input. The Game layer captures the array/table schema through safe inspection and retains actor schemas and callback order.

3. Native Boolean tables reuse released key slots. A repeated press no longer allocates another byte key. Small key sets retain their slots; maps above 64 stored keys clear nil slots every 64 releases. At most 127 inactive slots remain between cleanups. Nil slots are excluded from reads and state enumeration. A 4,096-distinct-key regression checks bounded inactive storage and preserved false entries. The first write of a new key may still allocate.

No production unsafe code was added. Unsupported table value types, numeric map keys, mutable arrays, unproven indices, metatables and overlapping incompatible state ownership retain rejection/fallback behavior. Hosts must declare complete raw-table state and exclude outside observers. General table iteration, loops and interprocedural calls remain outside this compiler subset.

## FoF compatibility

A fresh normal application build at baseline failed the original FoF startup smoke: no retained VM, no changing actor frames and no sound operations. Normal gameplay requested offline compilation, which rejects registered input callbacks. Loading now prefers compiled playback and retries only the existing exact runtime-required rejection with live loading/clock-handoff flags. The strict preparation API and unrelated errors retain their behavior. This policy is generic and has no song title, source hash or handwritten FoF adapter.

The changed normal application build passes the same source smoke: 81 actors, 239 changing visual frames, 3,114 final mesh vertices, seven sound operations and no reported Lua errors over 241 frames. This proves restored interactive-source loading and animation, not whole-minigame parity. The full FoF scene still retains Lua for queued updates, ECS/physics, rendering and other authored behavior. The original input-handler migration is available as a detached native owner; it is not independently substituted into that live scene, where Lua still observes its held-state tables.

The existing Single captured-control replay also passes through production preparation: 448/448 frames, 59 input events, 19 stage samples/209 fields, 15,387 submitted draw samples, 699,774 vertices and 223 text samples, with zero mismatches or errors. Its trace hash, source archive and all 39 song files are verified. This is the test-support replay harness; the separate normal application smoke establishes startup without that feature. The replay ends at its captured beat limit and does not certify whole-song completion or framebuffer pixels. No native observations are fed into authored behavior as precomputed actions.

## Measurement

The generic `owned_tables` example reads source, entry point, field/action schema and event sequences from caller JSON. It checks each initial Lua/native result, ordered action digest and complete present table state. The loading VM is then destroyed (verified with an application-data destructor) before native replay/timing. Native execution does not call Lua. The flat case is a complete runtime input-to-visible-action interaction; the original FoF case changes held state only.

Three alternating Lua/native process pairs each run ten samples, discarding the first, with 98,304 input events per sample. Complete preparation measures source loading, schema capture, native compilation and machine construction/destruction in six batches of 16, discarding the first. Native timing includes decoding caller JSON scalar views into a stack input frame. Lua timing reuses already-created event tables. This conservative input-decoding asymmetry is unchanged between native candidates.

| Migration / stage | Cycles/event Lua → native | Events/s Lua → native | Native allocations/event | Native requested bytes/event |
|---|---:|---:|---:|---:|
| Flat state/action, initial lowering | 976 → 664 | 2,244,783 → 3,301,151 | 0.2604 | 1.2917 |
| Original FoF handler, array lowering | 558 → 521 | 3,930,729 → 4,207,715 | 0.1771 | 0.6979 |
| Flat state/action, final slot reuse | 920 → 646 | 2,381,655 → 3,389,127 | 0 | 0 |
| Original FoF handler, final slot reuse | 541 → 485 | 4,052,136 → 4,521,824 | 0 | 0 |

All rows have zero reallocations/event. Lua also has zero measured allocations after warmup. Before these lowering mechanisms, the new interactions were rejected by the native compiler and required Lua; the first two rows compare that authored execution with the newly available native path. They are distinct migrations, not additive reductions for one workload.

The first exact-inactive-count cache trial eliminated allocations but measured approximately equal Lua/native cycles (562/561). The retained simpler cache avoids per-press accounting. An early FoF tape correlated player two with release events; its raw evidence is retained as limited coverage. The reported FoF tape independently varies player and event kind, including first press, repeat, release, unknown kind and absent/unrecognized player values.

The isolated third-change comparison uses frozen native binaries, identical harness/source input and three alternating process pairs:

|---|---:|---:|---:|---:|
| Flat state/action | 629 → 587 | 3,476,330 → 3,730,589 | 0.2604 → 0 | 1.2917 → 0 |

Reallocations remain zero. Complete native preparation in this comparison changes from 701,083 to 734,762 cycles for flat state and 1,000,412 to 1,018,329 for FoF. Allocation/reallocation counts remain unchanged; requested bytes increase by 8/16 respectively. The cache is retained for its demonstrated warmed allocation reduction and bounded inactive key ownership; it does not improve CPU cycles on every case.

|---|---:|---:|---:|---:|

These tiny interactions trade more loading work for VM-free gameplay. No loading speedup is claimed. Requested bytes count cumulative Rust allocation/reallocation requests, not peak resident memory; native malloc outside the instrumented allocator is excluded.

Final native owned payload is 2,465 bytes for the flat interaction and 2,513 bytes for the original handler. Lua allocator usage after collection is 47,242 and 53,239 bytes respectively. These are different scopes: native excludes hash control/allocator and Arc bookkeeping, while Lua includes the standard VM, authored module and cached event-table fixture. The figures establish detached ownership and approximate payload size, not a precise total-memory ratio.

## Validation limits

All 68 focused checks pass: 31 SDK programs/table tests, 17 actor-input tests, 15 compiled-input/loading-policy tests, four method/root/stack tests and one renderer differential. The latter compares 270 exact gameplay-frame and OpenGL-pixel pairs across nine fixtures. The intentional stack-unwind probe emits a caught panic and passes. The source-included playback harness also compiles; its full test suite was not run. The original FoF module fixture is byte-for-byte identical to its source (`da8d1f5a001a392e5be8670534a7b0d161d078bf828b3aca98c9e4b27eed8e30`); a Git attribute preserves those bytes on every host. The two-player indexed fixture runs through the same actor-input and renderer differential as existing migrations.

The six known existing Song Lua failures were not re-audited or fixed; no full Song library or full-song suite was run. This pass does not establish whole-song, cross-theme or full FoF framebuffer parity. SDK mechanisms own no game/theme policy; Game owns capture, actor application and loading fallback; Theme presentation is unchanged.
