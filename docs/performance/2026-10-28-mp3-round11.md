# MP3 decoder: eleventh optimization pass

The production baseline is `80475b897`. Three safe Rust optimizations batch
side-information fields, decode LSF factors into their final arrays, and speed
zero-granule dispatch and hybrid tails. Public APIs, coefficient tables and
resident decoder fields are unchanged. Whole-file results remain mixed; the
strongest gains are in the specific parser, LSF and empty-frame workloads.

## Measurement method

The final stages are `round11-baseline`, `round11-side`, `round11-lsf`, and
`round11-word-zero`. All use identical probes, 13 fixtures, compiler,
configuration, bench profile and fixed Cargo build path. The driver validates
saved source, executable, helper and fixture hashes. Seven fresh processes per
stage rotate their order. Each process reports the median of eleven measured
batches after warmup, using `QueryThreadCycleTime` on Windows logical CPU 2.
Compilation and correctness checks run outside decision timings. Capture-time
initial samples are excluded from decisions.

There are **184 workloads and 5,152 final observations** in
[raw data](2026-10-28-mp3-round11.tsv) and
[manifests, medians, ranges and MAD](2026-10-28-mp3-round11.json). Eighteen new side-information
probes cover three MPEG versions, both channel counts, and long, pure-short and
mixed-short layouts. Setup and packet construction are untimed. A side-info
operation parses one complete frame's metadata; an LSF operation reads one
granule/channel. Empty-frame probes retain their decoder across iterations.
CPU throughput is the inverse cycle ratio; nanoseconds remain in the raw data.
No process observations are discarded.

All six heap counters are zero in all 5,152 final observations and all 5,152
screen observations. There is **no heap-allocation reduction** in this pass.

## 1. Batch side-information fields

The parser already requires the complete fixed-size side-info slice before
reading fields. Its header prefix now uses one checked read for main-data
offset, private bits and SCFSI flags. Each granule uses three reads: 29 bits for
part2_3 length/big_values/gain, 5 or 10 bits for compression/window switch, and
25 or 24 bits for the remaining layout and flags. Shifts and masks assign the
individual fields directly.

This replaces 13 or 15 per-granule MPEG-1 reads, and 12 or 14 LSF reads, with
three. MPEG-1 stereo side info needs thirteen reads overall instead of 62 for
long layouts or seventy for switched layouts. Each granule still occupies
exactly 59 MPEG-1 or 63 LSF bits, independent of block shape.

| MPEG-1, stereo long | 328.04 | 203.76 | 37.9% | 1.610x |

The initial full-slice check still returns Truncated before field validation.
Within each granule, big_values is checked before switched-block validity;
granule/channel order and unused Huffman selectors retain their behavior.
Reading the packed tail earlier cannot create an intervening truncation error:
the fixed-length side-info slice is already present.

## 2. Write LSF factors directly to their destination

The old path decoded into two 36-byte temporary arrays, then copied values and
widths into long/short factors. It now supplies the existing packed-word reader
with slices of the final arrays. Long blocks use 21 entries; pure short blocks
use the first 36 flattened short entries. Mixed blocks first read six long
factors from the first partition, then decode the remaining 27 into short bands
3–11. That six-factor prefix is exactly the first existing packed chunk in
every LSF class, preserving word boundaries and error behavior.

The two temporary arrays, their initialization, and the copy/reorder pass are
removed. Default zero fields, uncoded top bands, transmitted widths, flags and
cursor accounting retain their values.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Long, normal, compression 399 | 235.13 | 204.64 | 13.0% | 1.149x |
| Pure short, normal, compression 399 | 399.29 | 266.41 | 33.3% | 1.499x |
| Pure short, intensity, compression 399 | 273.76 | 187.06 | 31.7% | 1.463x |
| Mixed, normal, compression 399 | 342.68 | 274.29 | 20.0% | 1.249x |
| Mixed, intensity, compression 399 | 245.97 | 171.91 | 30.1% | 1.431x |

All eighteen measured nonzero LSF cases improve at this stage, by 6.4–34.1%.
The explicit scratch buffers shrink by 72 bytes; the generated reader stack
reservation shrinks by only sixteen bytes because register allocation and other
temporaries also change. No 72-byte peak-stack saving is claimed.

## 3. Use packed zero detection and a direct hybrid-tail path

A private predicate ORs the bit patterns of all 576 f64 values, then masks the
sign bit. It is true for either zero sign and false for every nonzero magnitude
bit, including subnormals, infinities and NaNs. OR cannot cancel a nonzero bit.
The compiler emits packed integer OR operations for this reduction. The same
predicate selects zero spectra before hybrid processing and zero subbands
before synthesis; dense data pays for a full scan instead of an early exit.

For zero spectra, a private hybrid method emits the retained overlap tail,
applies the same odd-band/time sign inversion, and clears overlap. It retains
the addition of positive zero so negative-zero rounding matches normal
overlap-add. Aliasing, transform setup, per-band zero searches and window work
are skipped. The public general hybrid method keeps its behavior, including
input mutation. FrameDecoder's private spectra are overwritten before later
use. Drain uses the same tail method and also removes a 4,608-byte spectral
clear per channel; drain alone is not separately timed.

| FrameDecoder.decode, round11-word-zero | 3515 | 1272 |

Counts describe standalone function bodies, not retired instructions or total
program size. The side parser loses 44.2% of its static instructions but reserves
eighty more stack bytes. Direct LSF writes add 101 static instructions while
reducing dynamic copying and sixteen stack bytes. The final decode body grows
by 460 instructions and sixteen stack bytes versus the preceding stage; the
new tail/zero helpers are inlined rather than emitted standalone. Stack figures
exclude callee/return-address use and do not establish peak call-chain use.
[Assembly hashes, calls, counts and layout commands](2026-10-28-mp3-round11-codegen.json).

All stages measure the same resident layouts on this compiler/target:
FrameDecoder 51,568 bytes/alignment 16; ScaleFactors 136/8; Hybrid 4,608/8;
Synthesis 8,208/16. No decoder fields, immutable tables or heap storage are added.

## Replaced silence experiment

The first screen used the direct hybrid tail with scalar float equality scans.
It improved four empty cases but regressed MPEG-1 mono by 5.7% and MPEG-2 stereo
by 6.1% versus its preceding LSF stage. That version is replaced by packed
zero detection. Its 5,152 observations remain in
[screen data](2026-10-28-mp3-round11-screen.tsv),
[screen summary/manifests](2026-10-28-mp3-round11-screen.json),
[code generation](2026-10-28-mp3-round11-screen-codegen.json), and
[corpus verification](2026-10-28-mp3-round11-screen-corpus.json).
The final comparison reuses the same immutable baseline/side/LSF executables
with the revised fourth stage and repeats all seven rotations. Do not combine
screen and final process observations into one measurement set.

## Exact behavior and validation

All **70 tests**, strict all-target Clippy, scoped formatting and whitespace
checks pass. New tests compare the direct hybrid tail with the general path
after dense, subnormal, NaN and signed-zero histories, including exact overlap
bits, repeated zero granules, and resumed input. The zero predicate checks every
bit at every coefficient position with both background zero signs: 73,728
single-bit cases, plus 3,456 special infinity/NaN cases and two all-zero cases.

The verifier adds **114,584 side-info observations**. For all version/channel
configurations it checks single-bit changes to five valid layout templates,
4,096 deterministic random byte patterns, truncated lengths, exact lengths and
ignored trailing bytes. Each serializes the full result or exact error. The
existing 370,080 LSF observations, MPEG-1 bounds, full-domain requantization,
stereo, hybrid, synthesis, CRC and Huffman traces remain.

All four final stages produce the same **483,129,574-byte** trace for
**80 files** (42 encoder, 36 seek and two protected CRC fixtures), SHA-256:

`18c8021bab3df5a6f1a24ffe18d42dc8893c3b04fff915ae9bd3894317ae498e`

The selected 13-file trace is 458,361,574 bytes with SHA-256
`ce84bd1ad8ea366f9f67515ef0167b8ab5a8e8fee87941f542c2a8d0be87d159`.
These traces contain kernel/error observations as well as PCM; expanded
coverage changes size and hash from earlier passes.
