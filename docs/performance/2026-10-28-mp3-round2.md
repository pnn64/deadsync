# MP3 decoder: second optimization pass

The baseline for this pass is production MP3 source at `927cc6ad4`, after the
first three retained optimizations. Measurements use the same resident-input,
fixed Cargo build path, pinned Windows thread and `QueryThreadCycleTime` method
as [the first pass](2026-10-28-mp3.md). Each process takes the median of eleven
measured batches after warmup; comparisons interleave seven process runs per
binary. Nanoseconds, allocation counters, source/fixture/binary hashes,
compiler/configuration and dispersion remain in the raw TSV and JSON records.

## 1. Direct unit-coefficient requantization

Return the scale directly for +1 and negate it for -1. Retain the zero result
and original `powf`/sign/multiply path for every other i16 value. This removes a
power call, sign operation and multiplication for each unit coefficient, which
includes every nonzero count1 coefficient. There is no lookup table, cache,
initialization cost, new dependency or unsafe code.

| Workload | Before cycles/op | After cycles/op | Cycle reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Long requantization, coefficients 0/±1/±2 | 21,496.96 | 14,529.36 | 32.4% | 1.480x |
| Short requantization, same coefficients | 22,277.28 | 14,368.91 | 35.5% | 1.550x |
| Mixed requantization, same coefficients | 22,567.89 | 13,981.93 | 38.0% | 1.614x |
| Decode 44.1 kHz stereo | 32,789,241 | 30,804,850 | 6.1% | 1.064x |
| Decode 22.05 kHz mono | 11,967,359 | 10,858,776 | 9.3% | 1.102x |
| Decode 8 kHz stereo | 7,428,428 | 7,003,696 | 5.7% | 1.061x |

Wide-magnitude requantization controls range from +0.2% to +2.5% cycles; their
input contains only one zero and no unit coefficients. Other untouched probes
vary by about 3%. All observed allocation counters are zero before and after.

Evidence: [raw observations](2026-10-28-mp3-unit-power.tsv),
[summary and manifests](2026-10-28-mp3-unit-power.json). Saved stages:
`round2-baseline`, `unit-power`, under `target/mp3-perf-20261028`.

## 2. Direct count1 table B decoding

Table B encodes every four-bit presence mask as its four-bit complement. Read
those four bits directly, XOR with 15, and retain the original nonzero-sign
processing and cursor-atomic failure handling. This removes four prefix-tree
steps per table-B symbol. Its 15 unused tree nodes and root entry are removed:
table storage falls from 5,672 to 5,610 bytes, with no runtime construction.
The generator verifies the fixed-width complement property against all 16
original numeric codewords and retains all 1,410 independent CSV fixtures.

| Workload | Before cycles/op | After cycles/op | Cycle reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| 256 count1 table-B quads | 9,175.54 | 8,082.65 | 11.9% | 1.135x |
| 256 table-A quads, control | 7,646.72 | 7,585.92 | 0.8% | 1.008x |
| Decode 44.1 kHz stereo | 26,742,235 | 26,501,222 | 0.9% | 1.009x |
| Decode 22.05 kHz mono | 9,512,691 | 9,243,474 | 2.8% | 1.029x |
| Decode 8 kHz stereo | 6,104,734 | 5,809,068 | 4.8% | 1.051x |

All allocation observations remain zero and verification fingerprints match.
Untouched controls show code-layout/machine variation, including a 9.6% shift
in the short requantization probe; the 0.9% decode change is correspondingly
weak evidence in isolation. The targeted table-B gain exceeds the variation
in its unchanged table-A control and eliminates known work and stored data.

Evidence: [raw observations](2026-10-28-mp3-count1-direct.tsv),
[summary and manifests](2026-10-28-mp3-count1-direct.json). Saved stages:
`count1-before`, `count1-direct`.

## 3. Direct mid/side-only coupling

After the existing joint-stereo shape check, mode 2 couples the two spectral
planes directly and returns. This bypasses initialization and examination of
576 intensity flags when intensity stereo is disabled. Independent sample
pairs use the same ordered sum/difference and multiplication as before; modes
0, 1 and 3 retain their existing behavior. No buffer or unsafe code is added.

| Workload | Before cycles/op | After cycles/op | Cycle reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Mid/side coupling, one granule including input copy | 2,481.38 | 912.62 | 63.2% | 2.719x |
| Decode 44.1 kHz stereo | 31,034,117 | 30,615,529 | 1.3% | 1.014x |
| Decode 8 kHz stereo | 6,828,536 | 6,803,183 | 0.4% | 1.004x |

The end-to-end changes in this isolated comparison are small; the measured
benefit is primarily the coupling kernel. Mono decoding also shifts by 1.9%
despite never calling stereo coupling, illustrating code-layout/control
variation. Allocation counters remain zero and all verification bytes match.

Evidence: [raw observations](2026-10-28-mp3-mid-side.tsv),
[summary and manifests](2026-10-28-mp3-mid-side.json). Saved stages:
`mid-side-base`, `mid-side-direct`.

not a uniform speedup for every input. Both gains and regressions remain in
[format TSV](2026-10-28-mp3-round2-formats.tsv) and
[format JSON](2026-10-28-mp3-round2-formats.json).

## Correctness and reproduction

All saved stages use identical probes. Besides the first pass's DSP and PCM
checks, verification now includes 11,520 requantization granules: every u8 gain,
all nine rates, normal/start/stop/short/mixed shapes, both scale/preflag settings,
varying full-u8 factors/subblock gains, unit coefficients, escape magnitudes,
and both i16 extrema. Every emitted f64 bit matches the baseline fingerprint.
The six requantization, four Huffman and one flag probe extend hot-path CPU and
allocation coverage without changing timed production behavior.

Final verification also covers 8,640 stereo cases across all four mode-extension
values, nine sample rates, five block shapes, sixteen intensity factors and
three right-channel zero-bound patterns, including signed zeros, subnormals,
overflow and infinities. Original and final source produce identical bytes.

A complete original/final comparison of 42 encoder files and 36 CBR/VBR seek
files also passes: **78 files**, **262,348,032 bytes** including DSP probes,
SHA-256 `3cdedaea6912f25447b16d9919b4d638eba3e19896964098512df70341cb78cf`.
[Input hashes, commands and output evidence](2026-10-28-mp3-round2-corpus.json).

After each of the first two changes, all 48 crate integration tests and all-target
Clippy with `-D warnings` pass. Scoped rustfmt and `git diff --check` pass.
The existing Huffman suite independently checks 175,680 pair cases and every
quad codeword/sign mask/bit offset, including every incomplete prefix and sign
tail with unchanged cursor positions. Regeneration reproduces the Rust tables,
CSV fixtures and JSON metadata exactly; the CSV itself is unchanged.

The new mid/side regression checks exact f64 equations (including signed zero,
subnormals and overflow), every matching u8 block-type value, both mixed flags
and all three MPEG versions. Mismatched shapes must fail before changing input.
All **49** final crate integration tests and all-target Clippy with
`-D warnings` pass. Final checks set `CARGO_INCREMENTAL=0` to bound cache growth.

The final baseline is saved as `round2-all-baseline`, rebuilt with current
probes from the original `round2-baseline` production snapshot. `--source-stage`
now explicitly combines saved production source with today's probes. Old
separate-path build dependencies and this task's incremental caches were
removed to free disk space; every saved executable and source snapshot remains.


runs should not be multiplied to predict total decoder performance.
