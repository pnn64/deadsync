# MP3 decoder optimization measurements

Measured on Windows x86-64, Intel Xeon E5-2696 v4, using the repository's
bench/release profiles (opt-level 3, LTO, static CRT, bench debug symbols).
The existing benchmark helper pins the measuring thread to logical CPU 2 and
uses Windows `QueryThreadCycleTime`. Reported cycles exclude descheduled time;
nanoseconds are secondary. Each process takes the median of eleven measured
batches after warmup. The tables below use the median of seven interleaved
process runs per saved binary. Raw TSVs include every observation; JSONs include
dispersion, source/fixture/binary SHA-256 hashes, compiler and configuration.

Fixture I/O, packet framing and output verification happen outside timing.
Decode probes reuse a warmed decoder and consume all PCM planes from all frames
in each resident file. Each bits operation reads 512 fields; synthesis operates
on one 32-sample slot; hybrid operates on one dense 576-line granule.

## 1. Contiguous synthesis matrix outputs

Transpose the stored synthesis coefficients and accumulate across independent
output lanes. Each lane retains its original 32-term floating-point operation
order. This exposes contiguous independent arithmetic to compiler vectorization
without explicit intrinsics or unsafe code. It replaces 64 serial dot products
with direct updates of the 64-value ring slice; there is no intermediate buffer.
The coefficient count and memory footprint are unchanged. Generated table source
has 32 fewer rows.

| Workload | Before cycles | After cycles | Cycle reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Synthesis slot | 3,118.28 | 1,831.11 | 41.3% | 1.703x |
| Decode 44.1 kHz stereo | 43,464,512 | 32,990,411 | 24.1% | 1.317x |
| Decode 22.05 kHz mono | 14,354,861 | 11,683,107 | 18.6% | 1.229x |
| Decode 8 kHz stereo | 9,270,364 | 7,448,952 | 19.6% | 1.245x |

All probes have zero measured allocations, reallocations, frees and allocated
bytes before and after. Untouched hybrid controls vary by up to 3.4%; the decode
improvements and synthesis gain are substantially larger than that variation.

Evidence: [raw observations](2026-10-28-mp3-synthesis.tsv),
[summary and manifests](2026-10-28-mp3-synthesis.json).

## Correctness and reproduction

The benchmark emits raw little-endian f64 hybrid/synthesis values, mutated
spectra, and f32 decoded PCM outside timing. Its comparison script requires
identical SHA-256 output fingerprints before running paired measurements.
Coverage includes all 576 negative basis impulses, dense random input, zero and
signed-zero input, overlap histories and synthesis ring wraparound, three seeds,
normal/start/stop/short/mixed blocks (including the four-subband 8 kHz case), and
the three encoded files. The compared production stages preserve every emitted
bit. Existing crate tests cover framing errors, Huffman boundaries, spectral
equations, decoding, streaming, gapless playback and seeking.

After stage 1, all 48 crate integration tests pass; all-target Clippy with
`-D warnings`, scoped rustfmt and `git diff --check` pass. Regenerating DSP
tables from the recorded numeric dewindow input produces the exact benchmarked
source. Validation uses separate `target/mp3-checks-20261028` and
`target/mp3-lints-20261028` directories because an existing executable in the
default target directory was locked by another process.

The probes and capture driver are in `crates/deadlib-audio/decode/mp3/benches/kernels.rs`
and `scripts/benchmark.py`. Baseline production source is MP3 at `2dff293a5`.
The snapshots are retained under `target/mp3-perf-20261028`; manifests in the
tracked JSON identify their exact inputs and binaries. Capture each production
stage before editing the next one:

```powershell
python crates/deadlib-audio/decode/mp3/scripts/benchmark.py --capture baseline `
  --fixture target/deadlib-mp3-reference/encoder-corpus/libmp3lame-44100-2.mp3 `
  --fixture target/deadlib-mp3-reference/encoder-corpus/libmp3lame-22050-1.mp3 `
  --fixture target/deadlib-mp3-reference/encoder-corpus/libmp3lame-8000-2.mp3
# Apply the synthesis change, then repeat capture with --capture synthesis.
python crates/deadlib-audio/decode/mp3/scripts/benchmark.py `
  --stage baseline --stage synthesis --runs 7 `
  --output docs/performance/2026-10-28-mp3-synthesis.tsv
```

These are CPU-cycle measurements on one machine and compiler configuration;
they do not establish equivalent speedups on other architectures.
