# MP3 decoder optimization measurements

Three retained safe-Rust changes reduce complete frame-decoder CPU cycles by
29-34% on the measured files. All measured hot paths remain allocation-free.
The original scalar arithmetic order is preserved for every output sample.

## Method

Windows x86-64, Intel Xeon E5-2696 v4, rustc 1.99.1 / LLVM 23.1.1, repository
bench/release profiles: opt-level 3, LTO, static CRT, bench debug symbols.
The existing benchmark helper pins its thread to logical CPU 2 and reads
`QueryThreadCycleTime`. CPU cycles exclude descheduled time. Wall-clock
nanoseconds are retained as secondary observations and can include contention.

Each process reports the median of eleven measured batches after warmup. The
primary comparison uses seven rotating, interleaved process runs per binary.
All four production stages were rebuilt through one fixed Cargo package/build
path and copied to separate executables before the next rebuild. This controls
package identity and build-path differences. Exact source/fixture/binary hashes,
compiler, profiles, configuration, raw observations and dispersion are recorded
in [final TSV](2026-10-28-mp3-final.tsv) and [final JSON](2026-10-28-mp3-final.json).

Fixture I/O, packet framing, allocation setup and output verification are
untimed. Decode probes reset and reuse a warmed decoder, decode every resident
frame and expose every PCM plane to `black_box`. A synthesis operation is one
32-sample slot; hybrid is one dense 576-line granule. Bit-reader probes serve as
unchanged controls and read 512 fields per operation.

## Retained changes

1. **Synthesis matrix output lanes** (`569a8334f`). Transpose the stored 64-by-32
   matrix and accumulate directly into its existing 64-value ring slice. Each
   lane retains its original 32 multiply/add operations in order. Replace 64
   serial dot products and final assignments with direct lane accumulation. Table source loses 32 rows;
   coefficient count and storage are unchanged. In the fixed-build comparison,
   synthesis falls from **2,908.02 to 1,690.61 cycles/slot**: **41.9% fewer
   cycles**, **1.720x CPU throughput**. Full decoding improves by 18.5-22.4%.
2. **Long hybrid transform output lanes** (`90dff7ed3`). Transpose the 36-by-18
   long IMDCT coefficients and accumulate directly into the existing transformed
   array, followed by the original window multiplication. Remove the serial
   dot-product temporary. Table source loses another 18 rows; storage is
   unchanged. Normal long hybrid falls from **15,962.70 to 12,144.28
   cycles/granule**: **23.9% fewer cycles**, **1.314x CPU throughput**. Start and
   stop blocks improve by 21.6% and 21.1%. Full decoding improves by another
   11.1-15.8%. Short transform code/data remain unchanged.
3. **Contiguous synthesis window spans**. Exchange the output/group loop order
   and resolve two contiguous 32-value ring spans per group. Remove **496 of
   512 ring-wrap masks per slot** and each output's serial sum temporary. The
   ring offset remains a multiple of 64; both spans fit within the 1024-value
   array even at wraparound. Each output performs its original sixteen ordered
   multiply/add operations. An eleven-run paired confirmation measures
   **1,629.33 to 1,488.50 cycles/slot**: **8.6% fewer cycles**, **1.095x CPU
   throughput**. Complete decoding uses 2.8-3.5% fewer cycles in that repeat.
   See [paired TSV](2026-10-28-mp3-dewindow.tsv) and
   [paired JSON](2026-10-28-mp3-dewindow.json).

No production unsafe code, dependencies, public API changes, heap buffers,
extra transform tables or coefficient approximations were introduced. Table
regeneration from the recorded numeric dewindow input reproduces the measured
source exactly. SIMD opportunities come from independent contiguous output
lanes; there is no floating-point reassociation or fused multiply-add rewrite.

## Cumulative results

Seven-run comparison of all four fixed-build stages, cycles per resident file:

| File | Baseline | Matrix synthesis | Long hybrid | Contiguous window | Total reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 44.1 kHz stereo | 40,928,958 | 31,761,322 | 27,193,417 | 26,926,393 | 34.2% | 1.520x |
| 22.05 kHz mono | 13,412,328 | 10,756,378 | 9,565,262 | 9,522,459 | 29.0% | 1.408x |
| 8 kHz stereo | 8,406,740 | 6,853,010 | 5,773,180 | 5,852,199 | 30.4% | 1.437x |

The window change has a small end-to-end effect: the four-stage run shows
+1.4% cycles for the 8 kHz file and reductions under 1% for the other files.
The longer, dedicated eleven-run comparison instead shows reductions for all
three files, alongside a repeatable synthesis-kernel benefit. These runs and
unchanged controls expose the machine's variation; the report retains both
rather than selecting only the larger gains. Some untouched kernels shift
with the linked binary's code layout. Kernel gains should not be multiplied
together to estimate decoder throughput.

Every allocation observation in both final comparisons is zero: allocations,
reallocations, frees, allocated/freed bytes and peak bytes.

## Correctness

The same probes compare SHA-256 fingerprints of all emitted little-endian f64
hybrid/synthesis values, mutated spectra and f32 decoded PCM before timing.
All retained stages have the same fingerprint. This covers 10,440 hybrid
granules: all 576 negative basis impulses, dense random input, zero and signed
zero, overlap histories, three seeds, normal/start/stop/short/mixed blocks,
including the four-subband 8 kHz shape. It also covers 120 synthesis slots with
ring wraparound and the three measured encoded files.

A broader baseline/final comparison covers **78 files**: 42 encoder-corpus
files and 36 CBR/VBR seek-corpus files, mono/stereo at all nine supported sample
rates. The 129,637,632 emitted bytes (including DSP probes) match exactly:
`fefc14f997c324f6f17de05e1f1021add7f4aff1c97c2f4575b3fa014e735952`.
[Corpus commands, input hashes and output evidence](2026-10-28-mp3-corpus.json).

After every retained source change, all **48** crate integration tests pass.
These cover framing errors, Huffman boundaries, spectral equations, decoding,
streaming, gapless playback and seeking. All-target Clippy with `-D warnings`,
scoped rustfmt, Python syntax checks and `git diff --check` also pass. The live
Rust sources match the final benchmark snapshot by SHA-256.

The default test target initially contained a locked running `inspect.exe`, so
checks use this task's separate target directories. A later disk-full failure
interrupted checks and corpus output; disposable verification files from this
benchmark directory were removed and every interrupted check passed on retry.
Verification now streams directly into SHA-256 rather than materializing large
intermediate output files. Source snapshots and executable artifacts remain.

## Rejected experiments and earlier observations

The short-IMDCT rewrite showed no reliable benefit and was removed; a tiled
long-IMDCT version was also removed after its initial probe. A 64-bit bit-reader
rewrite greatly accelerated wide-field microbenchmarks but regressed complete
decoding. A direct byte path did not resolve its overall regression, including
in the fixed-path rebuild. Both reader changes and their exploratory test were
removed. They are not among the retained three optimizations.

Earlier separate-path measurements remain as diagnostic evidence:
[synthesis](2026-10-28-mp3-synthesis.json),
[long hybrid](2026-10-28-mp3-hybrid.json),
[combined hybrid trial](2026-10-28-mp3-hybrid-trial.json),
[word-reader trial](2026-10-28-mp3-bits.json),
[direct-reader trial](2026-10-28-mp3-bits-direct.json).
The fixed-build final comparison and dedicated window repeat above are the
primary performance evidence.

## Reproduction

The probes and driver are in `crates/deadlib-audio/decode/mp3/benches/kernels.rs`
and `scripts/benchmark.py`. Baseline production source is MP3 at `2dff293a5`.
Saved stages remain under `target/mp3-perf-20261028`, with source and binary
hashes recorded in the JSON manifests. Capture each production stage before
editing the next one; all captures now share `build/` as their Cargo path.

```powershell
python crates/deadlib-audio/decode/mp3/scripts/benchmark.py --capture baseline `
  --fixture target/deadlib-mp3-reference/encoder-corpus/libmp3lame-44100-2.mp3 `
  --fixture target/deadlib-mp3-reference/encoder-corpus/libmp3lame-22050-1.mp3 `
  --fixture target/deadlib-mp3-reference/encoder-corpus/libmp3lame-8000-2.mp3
# Repeat captures for each source change with a new --capture name.
# --source-stage NAME rebuilds an existing saved source snapshot.
python crates/deadlib-audio/decode/mp3/scripts/benchmark.py `
  --stage stable-baseline --stage stable-synthesis --stage stable-hybrid-long `
  --stage dewindow --runs 7 --output docs/performance/2026-10-28-mp3-final.tsv
python crates/deadlib-audio/decode/mp3/scripts/benchmark.py `
  --stage stable-baseline --stage dewindow `
  --verify-corpus target/deadlib-mp3-reference/encoder-corpus `
  --verify-corpus target/deadlib-mp3-reference/seek-corpus `
  --output docs/performance/2026-10-28-mp3-corpus.json
cargo test -p deadlib-audio-decode-mp3 --offline --target-dir target/mp3-checks-20261028
cargo clippy -p deadlib-audio-decode-mp3 --all-targets --offline `
  --target-dir target/mp3-lints-20261028 -- -D warnings
```

These CPU-cycle results apply to this machine and compiler configuration;
other architectures need their own measurements.
