# Song markers, text search, and query parsing

Baseline runtime source: `b3ad9b1ea`; measured on 2026-10-26. Three safe-Rust changes improve ordinary marker detection **1.868x**, long search misses **16.449x**, and plain typeahead parsing **1.458x**. Complete catalog construction improves **2.076x** for misses and **1.171x** for hits. Query parsing has measured regressions for tiny queries, short Unicode queries, and a 32-filter stress input; the tradeoff is detailed below. These are in-memory text and catalog measurements, with no claim of gameplay FPS or whole-application latency gains.

## Retained changes

1. `SongData::is_no_cmod` searches each contiguous field for the fixed marker, then checks the only possible match across the inserted space: title suffix `no` plus subtitle prefix `cmod`. The marker contains exactly one space. This removes the generic joined-byte matcher and its per-byte choice of title, separator, or subtitle. Empty/whitespace subtitles and ASCII case rules retain the same results.
2. `contains_ignore_ascii_case` retains the original scalar windows for haystacks shorter than 32 bytes. Longer strings check the first window, then use `memchr2` to skip to either ASCII case of the first needle byte. After four unsuccessful candidates, the remaining suffix uses the original scalar scan. The long loop stays out of line so short callers keep a small dispatch. This bounds dense-candidate overhead and preserves empty queries, immediate matches, non-ASCII bytes and overlong needles.
3. `parse_song_search_filter` finds ASCII `[` bytes and digit spans directly, copies intervening UTF-8 slices, and folds ASCII case once. Numeric conversion runs only after finding a closing `]`. A nonempty ASCII digit span can fail `u32` parsing only by overflowing; substituting `u32::MAX` preserves the original saturation. This removes per-character pushes, Unicode decoding/re-encoding, cloned `Peekable` iterators, and numeric work on incomplete filters. Difficulty/BPM thresholds, last-filter precedence, malformed/nested brackets, Unicode trimming and byte ranges remain identical. ASCII delimiters guarantee valid UTF-8 slice boundaries. Capacity remains the input byte length.

The production diff has **86 inserted / 60 removed lines**, excluding one test-only include. It removes one generic matcher and adds one dedicated long-search helper. It introduces no runtime dependency or unsafe Rust.

## Method and correctness

Windows x86_64 MSVC, Intel Xeon E5-2696 v4, rustc 1.99.1 / LLVM 23.1.1. Archived binaries use `--release --locked`, repository-default LTO, the baseline CPU target and static MSVC runtime. The existing helper pins the benchmark thread to logical processor 2 and reads `QueryThreadCycleTime`. Each process discards one warmup sample and reports the median of eleven measured samples. Samples repeat each marker/substring/query/control fixture 128 times and each catalog fixture 16 times. Four TSVs retain all **1,440 process/workload records**, elapsed time, allocation counters and executable SHA-256 values. No compilation started by this task overlaps retained comparisons; other shared-machine activity is uncontrolled.

Fixtures and results use `black_box`; construction stays outside measurement. Marker fixtures make 256 calls to the actual public method using one prepared song. Substring fixtures make 512 calls using a prepared haystack and needle. Long missing/late/dense cases use 128-byte bases; the Unicode case uses 64 repeated three-byte characters followed by a matching two-byte character. Query fixtures make 128 calls to the public `parse_song_search_live`, including its final trimming. The repeated-filter case has 32 `Abc[11]` fragments; the malformed case has sixteen incomplete long numeric filters. Catalog fixtures filter and sort 64 prepared songs, with transliterated matches on every third song, standard charts and varying meters. Miss/hit queries exercise the complete public builder, including formatting and owned results. The untouched difficulty-name lookup is the control.

Four new correctness tests compare with the complete search runtime frozen from `b3ad9b1ea` and the original marker helper. Marker checks cover all 128 ASCII case masks, every split, inserted ASCII bytes, whitespace and Unicode. Substring checks cover all ASCII bytes, threshold boundaries, every insertion position through 256 bytes, dense patterns, empty/longer needles and Unicode substrings at every valid character boundary. Query checks compare normalized text, pack/song byte ranges, difficulty/BPM fields and public live-query output across malformed/nested brackets, non-ASCII digits, overflow, repeated filters, slash positions, ASCII insertion, Unicode whitespace and large input. Catalog checks compare every candidate field, exact order and `Arc` song identity across empty/missing/matching queries, pack scopes, chart types and numeric filters.

Validation passes: **568 release tests** across chart/simfile/config (32 ignored), **316 debug tests** across chart/simfile (25 ignored), and **269 tests** in the final default-LTO measurement binary (19 ignored). All four measured archives pass the four new compatibility tests. Clippy for all chart/simfile targets passes with pre-existing warnings and three unused public functions in the frozen reference. The search source, new Rust files and complete changed chart method pass rustfmt. A full chart-file check differs only in the untouched `SongBackgroundLuaChange::new` constructor.

Source audits verify the frozen full search runtime and marker helper, reconstruct both starting production files by reversing only the intended changes and test include, compare final bytes with measured snapshots, and check every raw record's executable digest. Logs, sources, snapshots, executables and rejected trial data remain under `target/search-text/`.

An unrestricted vector loop slowed dense prefixes during screening. Repeated in-place token deletion slowed filter-heavy queries. A generic split-field marker trial regressed boundary and short-title fixtures in archived public-method measurements; its replacement is the fixed direct check. The first chunk-copy query trial updated a saturating integer while scanning every digit, including unfinished tokens. It was replaced with digit-span discovery and conversion only for closed filters. None of those trial implementations remains in production.
