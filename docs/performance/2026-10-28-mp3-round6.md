# MP3 decoder: sixth optimization pass

The production baseline is `3b980b795`. This pass measures borrowing in-frame
main data, skipping zero-width LSF work, aligning the synthesis matrix and
processing silent granules without redundant transforms. No public API changes
or production unsafe code are introduced.

## Measurement method

The fixed Cargo build/package path, repository bench profile, pinned Windows
thread and `QueryThreadCycleTime` protocol follow the previous passes. Seven
fresh processes per stage rotate five saved builds. Each process reports the
median of eleven measured batches after one warmup batch. Fixtures are resident
and packet creation stays outside measurement. Allocation counters measure one
additional operation after the timed batches.

The 89 workloads include eighteen LSF shape/intensity/compression combinations,
nine fresh-decoder frame probes, ten whole-file probes, and dense/zero synthesis
controls. The zero-history synthesis control includes cloning its primed state.
The public synthesis controls continue to run the ordinary matrix path; the
decoder's silent-granule path is exercised by decoded frames and unit tests.

All stages use the expanded verification trace, which includes 64 synthesis
slots per seed with dense input, a full history decay, positive/negative zero
and subnormals. Earlier passes' trace hashes cannot be compared directly with
this expanded trace.

## Input profile and measurement scope

The [reservoir usage observations](2026-10-28-mp3-reservoir-usage.tsv) and
[commands and input hashes](2026-10-28-mp3-reservoir-usage.json) show that all
115 Shine frames, all 221 synthetic long frames and all 391 synthetic short
frames use no back-reference. Other sampled streams generally have two such
frames; one often carries no main-data bits.

Fresh-decoder probes select the first zero-back-reference frame with nonempty
main data from each file. Constructor, decoding and destruction are timed and
allocation-counted. Packet creation/selection is outside measurement. The
short Media Foundation 8 kHz fixture has no nonempty main data, so it has no
such probe. Existing whole-file probes continue to reuse decoder capacity.

The direct payload view retains the physical payload's tail before returning,
so later frames can reuse its bytes after the caller changes or drops its
input. Back-references and invalid limits/truncations retain the existing
copying path. The public `Reservoir::push` API retains its independent input
lifetime and copying behavior.

## Results and retained changes

The five stages are `round6-expanded-base`, `borrowed-payload`,
`zero-width-lsf`, `aligned-matrix-final` and `silent-granules`.
[Raw observations](2026-10-28-mp3-round6.tsv) and
[manifests, dispersion and summary](2026-10-28-mp3-round6.json) retain all
3,115 observations, input/source/compiler/configuration hashes and allocation
counters. Capture-time initial logs are excluded from these comparisons.

### 1. Borrow the payload when no prefix is needed

All nine fresh-decoder probes change from one allocation and one free to zero,
with allocated/freed/peak bytes changing from **14-621 to zero**. All six
allocation counters are zero in the four changed builds. The baseline's
remaining eighty workloads already have zero allocation counters. Thus 3,052
of the 3,115 observations have six zero counters; the other 63 are the nine
baseline fresh-decoder cases across seven runs.

| Fresh decoder input | Before cycles/op | After cycles/op | Heap bytes before / after |
| --- | ---: | ---: | ---: |
| LAME 44.1 kHz stereo | 195,519.62 | 185,436.31 | 357 / 0 |
| Shine 44.1 kHz stereo | 211,598.00 | 210,377.00 | 382 / 0 |
| Media Foundation 44.1 kHz stereo | 171,388.31 | 196,809.12 | 350 / 0 |
| VBR 44.1 kHz stereo | 178,837.62 | 210,377.06 | 621 / 0 |
| Protected 22.05 kHz mono | 62,104.81 | 58,716.25 | 168 / 0 |

The benefit established here is allocation/copy removal. CPU medians are mixed;
for example, the VBR fresh-decoder case uses 17.6% more cycles. No general CPU
speedup is attributed to borrowing alone. During whole-file replay, this removes
43,544 bytes of assembly copies in the Shine input and all assembly copies in
the two synthetic inputs. The separately required reservoir-tail copy remains.

### 2. Skip fields that transmit no bits

An all-zero LSF width plan returns its already-defaulted factors after assigning
preflag and intensity scale. Other plans skip each zero-width partition while
preserving its destination offset. This removes zero-bit reads and, for the
all-zero plan, both staging arrays and their remapping from the executed path.
The established nonzero-field mapping remains.

| Zero-width LSF input | Before cycles/op | After cycles/op | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Long | 161.51 | 60.85 | 62.3% | 2.654x |
| Long intensity | 176.30 | 66.16 | 62.5% | 2.665x |
| Pure short | 258.70 | 60.85 | 76.5% | 4.251x |
| Pure short intensity | 283.97 | 65.21 | 77.0% | 4.355x |
| Mixed | 220.53 | 62.27 | 71.8% | 3.542x |
| Mixed intensity | 252.89 | 59.05 | 76.6% | 4.283x |

Plans containing nonzero widths also have lower medians in this incremental
comparison. Untouched synthesis controls improve by 6-9% at the same stage,
so small gains outside the zero-width cases are not isolated evidence of an
algorithmic improvement. MPEG-1 scalefactor logic is unchanged.

### 3. Guarantee aligned synthesis coefficient rows

The private matrix wrapper has C layout and 64-byte alignment; every 512-byte
row starts aligned. Numeric storage is still 16,384 bytes. The original binary
matrix addresses are 8 bytes modulo 16, while both retained aligned builds have
matrix addresses divisible by 64. The generator reproduces the wrapped source
byte for byte, and all 3,452 f64 coefficient bit patterns across eight tables
match the baseline, including signed zero.
[Table and PE-image audit](2026-10-28-mp3-matrix-alignment-audit.json).

| Public synthesis input | Before cycles/op | After cycles/op | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Dense slot | 1,365.40 | 1,408.93 | -3.2% | 0.969x |
| Zero slot | 1,373.04 | 1,254.46 | 8.6% | 1.095x |
| Zero slot with cloned history | 1,967.27 | 1,809.38 | 8.0% | 1.087x |

This is a modest targeted gain with a dense-input counterexample. The
standalone synthesis function's stack reservation changes from 536 to 520
bytes. Its static instruction count changes from 1,432 to 1,437; unaligned
packed moves fall from 560 to 528 and aligned packed moves rise from 106 to
168. These are static counts for the extracted function, not retired
instructions or a count of the entire binary.
[Code-generation commands, hashes and layouts](2026-10-28-mp3-round6-codegen.json).

### 4. Process silent granules without recomputing their matrix

The decoder tests the 576 subband outputs once per granule. Exactly zero input
uses a private silent-slot path, eliminating 2,048 multiply/add terms per slot.
The window still processes retained history. After sixteen silent slots have
overwritten the entire ring, it too can be skipped, eliminating a further 512
multiply/add terms per slot. The ring offset still advances. No tolerance or
subnormal flushing is used.

A one-byte countdown conservatively resets to sixteen on every ordinary public
matrix call, avoiding a zero scan in that public hot path. It fits in existing
padding: compiler-linked layout probes before and after report **8,208 bytes,
alignment 16 for Synthesis; 51,568 bytes, alignment 16 for FrameDecoder**.

| Decoded input | Before cycles/op | After cycles/op | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Empty Media Foundation 8 kHz frame | 61,569.50 | 13,170.00 | 78.6% | 4.675x |
| Synthetic long, fresh decoder/frame | 127,063.06 | 76,056.75 | 40.1% | 1.671x |
| Synthetic long, whole file | 27,321,055.50 | 25,358,176.00 | 7.2% | 1.077x |
| Shine, whole file | 23,541,923.00 | 26,405,959.50 | -12.2% | 0.892x |

The public dense-slot median changes from 1,408.93 to 1,382.59 cycles. The
public zero and zero-history controls become **15.7% and 14.7% slower**; they
still use the ordinary matrix path. Many untouched LSF/stereo controls also
move upward at this stage. The large silent-frame benefit is established, but
these measurements do not establish a uniform gain for ordinary audio.

## Correctness and checks

All five saved builds match the expanded 80-file trace exactly:
**315,904,960 bytes, SHA-256
`00b67d33380ba570f8534a0d8224f618f64fa384613d81d2aa2e4733264b3425`**.
The inputs include 42 encoder files, 36 seek files and two protected CRC files.
The trace also covers exhaustive CRC byte/state transitions, bounded bitfield
errors, hybrid/requantization/stereo states, signed zero and subnormals.
[Corpus commands and fingerprints](2026-10-28-mp3-round6-corpus.json).

All **64 crate tests** and all-target Clippy with warnings denied pass. New
reservoir tests cover pointer identity, 504 stateful input/back-reference/limit
combinations and input mutation before later reuse across six version/channel
shapes. The exhaustive LSF test now uses both maximum and position-varying
fields for all 512 compressions, shapes, intensity modes and LSF versions.
Silence tests compare exact f64 bits at every ring phase, including partially
filled history, positive/negative zero, subnormals, resumed audio and reset.
Scoped rustfmt and `git diff --check` pass. Baseline production source is
verified against `3b980b795`; final source/probes/helpers match the timed stage's
recorded hashes.

## Rejected direct-destination LSF variants

A chained-iterator implementation removed two 36-byte staging arrays, but a
three-run rotating comparison increased long nonzero-width reads from
266.21 to 444.71 cycles and other nonzero-width cases also regressed.
[Chain observations](2026-10-28-mp3-lsf-chain-screen.tsv),
[chain manifests and summary](2026-10-28-mp3-lsf-chain-screen.json).

A second variant split long/short output slices per partition and filled
widths in batches. It helped zero-width cases but slowed nonzero-width long
reads in the initial screen. Both direct-write variants were rejected in
favor of retaining the established mapping and removing only zero-width work.
[Partition observations](2026-10-28-mp3-lsf-partition-screen.tsv),
[partition manifests and summary](2026-10-28-mp3-lsf-partition-screen.json).

## Rejected per-slot public zero scan

An initial variant checked all 32 subbands inside every public synthesis call.
A three-run screen improved zero-slot and cloned-history probes by 4.154x and
2.743x, but dense slots changed from 1,286.16 to 1,473.20 cycles (+14.5%).
It was replaced by the granule-level check and conservative history countdown.
Untouched controls also moved in this screen, so it was a rejection signal,
not a precise attribution of the entire regression to the extra check.
[Screen observations](2026-10-28-mp3-synthesis-zero-screen.tsv),
[screen manifests and summary](2026-10-28-mp3-synthesis-zero-screen.json).
