# EX scoring kernels, 2026-11-04

Three retained changes in `deadsync-rules`, starting at `83c3161f9` on isolated
branch `perf/non-lua-kernels-20261104`. Lua and the main worktree's existing
edits remain outside this batch.

## Changes and exactness

1. EX/Hard EX earned points and possible-point totals use integer half-points.
   Each count is widened before multiplication or addition. The final integer
   is converted to `f64` and multiplied by `0.5`. Mine caps, saturated Fantastic
   counts, 10 ms subtraction and saturated hold/roll/tap totals are unchanged.
   This removes 13 source FMA call sites and 11 floating weight constants.
2. `normalized_blue_window_ms` accepts positive finite values with one unsigned
   bit interval, matching the existing core rate guard. Valid bit patterns are
   `1..0x7f80_0000`; subtracting one with wrapping and comparing against
   `0x7f7f_ffff` accepts exactly those patterns. Zeros, negatives, infinities and
   NaNs still return the same 10 ms default; accepted values keep their bits.
3. EX reconstruction selects failed/nonfailed code once before traversing the
   notes. A private const-generic scan removes failure branches and timestamp
   lookups from the nonfailed instantiation. Failed scans preserve row-time,
   hold-tail, invalid-time sentinel and missing-time fallback rules. Note order,
   tie selection, miss priority, fake/unjudgable notes and result handling are
   unchanged; no ordering assumption or early exit is added.

For earned EX points the doubled positive sum is at most
`23 * u32::MAX < 2^37`; subtracting the capped mine term cannot fall below
`-2 * u32::MAX`. Hard EX fits the same conservative bound, and possible-point
totals are at most `9 * u32::MAX`. All fit in the selected integer types and
are exactly representable in `f64`. Every intermediate in the original FMA
chains is also an exactly representable whole or half integer at these bounds.
Consequently conversion/halving preserves the original bits, including zero
and negative mine-only scores. Percentage division and rounding are unchanged.

All production code is safe Rust. The source diff adds 48 and removes 55 lines.
The specialized scan instantiates two loop bodies; this deliberately exchanges
code duplication for fewer runtime branches, without adding state or heap work.
Whole-application binary-size effects are not measured.

## Evidence and rejected candidates

Adjacent TSVs/manifests retain all measurements and exact source hashes:

- `baseline`: unchanged scoring functions and the initial six-case harness.
- `integer-points`: widened half-point arithmetic.
- `blue-bits`: integer scoring plus the window guard.
- `shared-filter`: discarded common eligibility branch. Mixed reconstruction
   was 1.000x and filtered reconstruction 0.958x; it was not retained.
- `resolved-counter`: discarded result-first resolution checks. The failed
   workload regressed to 0.931x, outweighing its mixed-case gain.
- `fail-specialization`: retained failed/nonfailed scan instantiations.
- `control`: exact pre-batch production sources with all ten final workloads.
- `final` / `debug`: first five-run measurement and debug correctness pass.
- `final-clean` / `debug-clean`: final verified sources after deleting two
   unused frozen wrapper functions flagged by Clippy. Timed functions and
   production code are unchanged by that test-only cleanup.

The unchanged control's median ratios range from 0.988x to 1.030x. Target
improvements are substantially larger. Compare paired variants within a
process; absolute cycle levels vary between stages. Initial six-case stages
used 500 batches per sample. Later stages use 3,000 for points/window kernels
and 500 for reconstruction. The final harness adds typical and extreme count
states, plus failures at the beginning and after the chart.

## Method and reproduction

Windows x86-64, Rust 1.99.1 / LLVM 23.1.1, CPU identifier
`Intel64 Family 6 Model 79 Stepping 1, GenuineIntel`. The script builds the
exact core/rules crates in a small workspace, offline, at optimization level 3
with LTO, no incremental compilation and the static MSVC runtime flag. It
archives source/executable/correctness-log SHA-256 hashes, compiler version,
dependency lockfile, manifest, commands and all raw logs at
`D:\deadsync-scoring-20261104` on the measurement machine.

Each benchmark thread is pinned to CPU 2. Twelve rounds alternate variants;
the first is discarded and the median of 11 `QueryThreadCycleTime` samples is
reported. The table uses medians of five process runs. Fixture construction,
correctness checks and allocation counting stay outside timing. Black-boxed
function pointers and inputs keep each result observable. CPU throughput is
before/after cycle counts; elapsed nanoseconds are retained in the TSVs.
These are kernel results, not a whole-game frame-rate claim.

From the repository root in PowerShell, with cached dependencies available:

```powershell
$env:DEADSYNC_SCORING_ARCHIVE = 'D:\deadsync-scoring-reproduction'
python scripts/benchmark_scoring.py control --baseline 83c3161f927d0a510691036e1dfb01031c6a542d
python scripts/benchmark_scoring.py final-clean --runs 5
python scripts/benchmark_scoring.py debug-clean --debug
$env:RUSTFLAGS = '-C target-feature=+crt-static'
$env:TEMP = "$env:DEADSYNC_SCORING_ARCHIVE\tmp"
$env:TMP = $env:TEMP
cargo clippy --offline --manifest-path "$env:DEADSYNC_SCORING_ARCHIVE\workspace\Cargo.toml" --all-targets --no-deps
```

The manifest's embedded lockfile records the dependency resolution and can be
used to pin it when recreating the workspace.

## Correctness and checks

All 156 core/rules tests pass in release and debug. New differential checks
compare exact bits for raw points, rounded percentages, possible-point ratios
and predictive tuples across extreme individual fields, all-maximum counts
and 20,000 deterministic randomized score states. Window checks cover edge
patterns and 20,000 random `f32` bit patterns, all six grades, exceptional
errors and saturated counters. Reconstruction compares 96 traces covering
missing/invalid time entries, fail-time extremes, held/let-go/missed/unresolved
holds, missing hold data, hit/avoided/unresolved mines, filtering and reversed
note order. Existing tests also compare individual and paired EX/Hard EX APIs.

Clippy completes with existing warnings in unmodified timing code and the two
unchanged nine-argument public scoring APIs. No warnings remain in the new
tests or the modified functions. Changed Rust passes rustfmt, the Python runner
compiles, and whitespace checks pass. The checks manifest records source/log
hashes and verification commands.
