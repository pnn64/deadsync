# MP3 decoder: third optimization pass

The production baseline is `e372c77f0`. The resident-input probes use the fixed
Cargo package/build path, repository release/bench profiles, pinned Windows
thread and `QueryThreadCycleTime` method described in
[the previous pass](2026-10-28-mp3-round2.md). Hot comparisons rotate seven
process runs per binary; each process reports eleven measured-batch medians
after warmup. Source/fixture/binary hashes, compiler/configuration, allocation
counters, nanoseconds and dispersion are retained in each TSV/JSON pair.

## 1. Cache small coefficient powers without changing their rounding

A `LazyLock` stores sixteen f64 powers (128 bytes of numeric data, plus its
synchronization state). The first requantization computes them with the same
runtime `powf` operation as uncached inputs. `black_box` prevents compile-time
constant folding from substituting differently rounded math results. The lock
is forced once per requantization; the resulting plain array reference is used
by all coefficient conversions. Zero and unit values retain their direct
paths. Magnitudes 2-15 use the cached power followed by the original sign and
scale operations; larger values retain the original runtime power call.

This removes repeated power calls for small non-unit coefficients, introduces
no production unsafe code or heap allocation, and leaves public APIs unchanged.

| Workload | Before cycles/op | After cycles/op | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Long requantization, 0/±1/±2 | 12,687.76 | 2,920.45 | 77.0% | 4.344x |
| Short requantization, same values | 13,649.61 | 3,890.64 | 71.5% | 3.508x |
| Mixed requantization, same values | 13,804.58 | 3,805.91 | 72.4% | 3.627x |
| Decode 44.1 kHz stereo | 29,257,595 | 29,410,476 | -0.5% | 0.995x |
| Decode 22.05 kHz mono | 10,340,206 | 9,786,298 | 5.4% | 1.057x |
| Decode 8 kHz stereo | 6,629,450 | 6,646,789 | -0.3% | 0.997x |

The stereo files are effectively flat in this comparison. Wide-magnitude
requantization controls range from 2.6% slower to 2.4% faster. The cache is
beneficial for the measured small-coefficient kernels and mono file, not every
input. All measured allocation counters are zero.

Evidence: [hot observations](2026-10-28-mp3-small-powers.tsv),
[hot manifests and summary](2026-10-28-mp3-small-powers.json). Saved stages:
`round3-base`, `small-powers` under `target/mp3-perf-20261028`.

### First-use cost

Twenty-one fresh processes per stage alternate the first all-zero
requantization. Fixture setup, thread pinning, TLS and cycle-query priming are
untimed; process launch is excluded. This deliberately exposes initialization
on a granule which needs no cached nonzero powers.

| Stage | Median CPU cycles | MAD cycles | Median ns |
| --- | ---: | ---: | ---: |
| Baseline | 33,144 | 3,292 | 9,700 |
| Cached powers | 60,143 | 7,243 | 20,700 |

Initialization adds roughly 27,000 CPU cycles in this cold probe. There is no
allocation churn. Warm throughput gains amortize this one-time cost; silent or
unit-only streams do not benefit from the cache. The costs and counterexamples
are part of the result, not omitted from the performance claim.

Evidence: [cold observations](2026-10-28-mp3-small-powers-cold.tsv),
[cold commands, manifests and summary](2026-10-28-mp3-small-powers-cold.json).

## Correctness and reproduction

The existing DSP, requantization, stereo and three-file PCM verification bytes
match the baseline SHA-256 fingerprint. A new independent scalar comparison
checks every i16 coefficient against runtime `powf`, including i16::MIN and
values on both sides of the cache boundary, at 24 gain/factor/scale settings.
It compares f64 bits rather than approximate values. The complete suite also
covers Huffman signs, escape boundaries and atomic error cursors.
All **50** crate integration tests and all-target Clippy with `-D warnings`
pass after this change. Scoped rustfmt and `git diff --check` pass.

```powershell
python crates/deadlib-audio/decode/mp3/scripts/benchmark.py `
  --stage round3-base --stage small-powers --runs 7 `
  --output docs/performance/2026-10-28-mp3-small-powers.tsv
# Fresh-process first-use sample; repeat with each saved binary, alternating order:
& <saved-binary> cold
$env:CARGO_INCREMENTAL = '0'
cargo test -p deadlib-audio-decode-mp3 --offline --target-dir target/mp3-checks-20261028
cargo clippy -p deadlib-audio-decode-mp3 --all-targets --offline `
  --target-dir target/mp3-lints-20261028 -- -D warnings
```

Results apply to this machine and compiler configuration. Ratios from different
comparisons should not be multiplied to predict total decoding performance.
