# MP3 decoder: fourteenth optimization pass

The production baseline is `f0ad3c990`. This pass changes the hybrid zero-band
check, count1-B decoding, and pair books 2/3. All changes use safe Rust and
preserve public signatures, decoder fields and numeric codewords. The code
generator prunes unused trees and builds direct immutable code/sign lookups.

## Measurement method

The cumulative stages are `round14-base`, `round14-first`,
`round14-bzero`, and `round14-direct-flags`. Each uses the same 209 workloads,
thirteen fixtures, compiler/configuration, bench profile and fixed Cargo build
path. The driver validates executable, source, helper and fixture hashes.
Seven fresh processes per stage rotate their order. Each reports the median of
eleven batches after warmup, using `QueryThreadCycleTime` pinned to Windows
logical CPU 2. Our compilation and correctness checks run outside decision
timings. Other workspace activity remains possible; capture-time initial
samples are excluded. No process observations are discarded.

The **5,852 observations** are in [raw data](2026-10-29-mp3-round14.tsv)
and [manifests, medians, ranges and MAD](2026-10-29-mp3-round14.json).
Huffman operations decode 256 symbols. Hybrid operations process 576 values
and include the input copy required because alias reduction mutates it.
New sparse probes specify how many initial input subbands are populated;
alias reduction can spread nonzero values to a neighboring band. Fixture
construction is untimed. Throughput below is the inverse cycle ratio;
nanoseconds remain in the raw data. All six measured Rust heap counters are
zero in every observation; no allocation reduction is claimed.

## 1. Recognize empty hybrid bands with a bit reduction

Each 18-value subband previously used short-circuit floating-point comparisons
against zero. The first sample still has its cheap early exit. When it is
zero, a packed reduction ORs the remaining bit representations and masks the
sign bit. Both signed zeros count as zero; every finite nonzero, infinity and NaN
counts as nonzero. The alias, transform, window and overlap arithmetic stay
unchanged. The compiler emits packed integer ORs for the reduction.

| Long, 31 populated input bands | 10,262.07 | 10,821.13 | -5.4% | 0.948x |
| Pure short, 0 populated input bands | 1,419.29 | 1,234.25 | 13.0% | 1.150x |
| Pure short, 1 populated input bands | 1,503.14 | 1,038.23 | 30.9% | 1.448x |
| Pure short, 8 populated input bands | 1,828.87 | 1,924.36 | -5.2% | 0.950x |

for all-zero mixed input. The eight-band pure-short case regresses 5.2%, the
31-band long case 5.4%, and dense long 1.4%. Many differences overlap recorded
MAD. The first-sample check retains the original cheap dense-data exit;
results include both the remaining costs and process variation.

## 2. Decode count1-B codewords and signs together

Every complete count1-B word, including signs, fits in eight bits. A 256-entry
u16 prefix table stores the total consumed length and an index into the
existing 81 signed-output records. A four-bit all-zero word returns directly.
For other words, one padded
lookahead and one checked skip replace the four-bit read, magnitude complement,
layout lookup, sign-field read and sign-offset calculation. The B path also
avoids a temporary cursor:
lookahead does not mutate it, and the skip checks its bound before advancing.
An incomplete word still leaves the caller's cursor untouched.

The shared eight-bit peek uses a two-byte window where physically available,
pads a missing second byte, and masks bits beyond the explicit bit boundary.
It never consumes lookahead bits. Its independent bit-by-bit test covers all
10,027,008 two-byte pattern/offset/bound combinations, plus empty input.
The generated table adds 512 bytes and reuses the signed-output records.

| --- | ---: | ---: | ---: | ---: |
| Table B, mixed | 5,196.22 | 4,688.96 | 9.8% | 1.108x |
| Table B, magnitude mask 0 | 2,860.96 | 3,052.81 | -6.7% | 0.937x |
| Table B, magnitude mask 1 | 5,286.22 | 5,064.52 | 4.2% | 1.044x |
| Table B, magnitude mask 5 | 5,220.59 | 4,761.39 | 8.8% | 1.096x |
| Table B, magnitude mask 15 | 5,008.99 | 4,849.19 | 3.2% | 1.033x |
| Table A, unchanged control | 4,229.11 | 4,986.60 | -17.9% | 0.848x |

Mixed table-B decoding improves 9.8%; nonzero-mask probes improve 3.2-8.8%.
The zero mask is still 6.7% worse at this stage, a substantial reduction from
the rejected table-only version's 65.2% regression. Table A's source algorithm
stays unchanged, but its shared caller changes: mixed A regresses 17.9% and
zero A 24.2% here. The final direct flag read restores zero A to 2,319.89 cycles
versus 2,470.69 at baseline (6.1% fewer); final mixed A remains 10.7% worse
(4,555.50 versus 4,115.63). No table-A speedup is claimed in general.

## 3. Decode small pairs with direct signed lookups

Pair books 2 and 3 fit their complete codeword and signs within eight bits.
Book 2 keeps its one-bit all-zero return; its other words use a 128-entry
suffix lookup after that initial zero bit. Book 3 uses a 256-entry complete
lookup. The u16 entries store the consumed length and two signed three-bit
values in -2 through 2. A padded peek, checked skip and two sign extensions
replace the tree walk and separate sign reads. A temporary book-2 cursor
retains atomic failure across the initial flag and the suffix; book 3 advances
only after the complete word is known to fit.

The larger pair body exposed an out-of-line sign path in the common-codebook
quantizer. Sign flags now read their fixed one-bit field directly from a
checked byte and bit mask, and the sign/flag helpers have explicit inlining.
This removes the per-sign helper/general-reader calls while retaining the
original errors and cursor behavior.

The generator validates that neither book has linbits or aliases, fills every
padded suffix, rejects collisions/incomplete tables, and omits their unused
trees. This removes 16 two-child nodes (64 bytes) while adding 768 bytes of
lookup entries, a net increase of 704 bytes. Numeric codewords and CSV fixture
bytes stay unchanged. Other codebooks retain their existing algorithms.

Mixed books 2/3 improve 46.8% and 32.9%. Their signed 2/2 patterns improve
55.9% and 65.4%, and book 2's zero pair improves 61.9%. Common pair-region
quantization recovers the rejected inlining regression and improves 6.3-9.7%
against the preceding stage. The fixed one-bit reader probe improves 10.6%.
The final quantizer body contains no calls to the sign helper, flag wrapper
or general bit reader; other ordinary calls are limited to its output clear,
with additional cold panic/error paths. The measured reduction includes the
lookup and one-bit-reader changes together.

## Rejected first versions

The separate seven-process screen also has 209 workloads and 5,852 observations.
An unconditional hybrid bit reduction improved zero-band cases, but dense long
regressed 6.9% and the 31-populated-band long case 12.4%. The final version keeps
the first-sample early exit. A table-only count1-B path regressed all-zero words
65.2%; the final path returns those words without table loads. A full book-2
lookup regressed its one-bit zero pair 22.0%; retaining its native first-bit
check also allows half the table to be removed. These results are not pooled
with final observations. [Screen raw data](2026-10-29-mp3-round14-screen.tsv),
[summary/manifests](2026-10-29-mp3-round14-screen.json),
[code generation](2026-10-29-mp3-round14-screen-codegen.json),
[corpus check](2026-10-29-mp3-round14-screen-corpus.json).

A second seven-process comparison tested the native zero shortcuts. It
confirmed the hybrid and count1-B gains, but common pair-region quantization
regressed 30-32% after the larger book-2 path changed inlining decisions.
Assembly showed new general-reader and sign-helper calls. Inlining the helper
alone exposed the underlying flag-reader call; forcing that wrapper inline
still left a general read of width one. The final direct flag read removes
that indirection. The two attribute-only variants were assembly diagnostics,
not timing decisions. [Second comparison raw data](2026-10-29-mp3-round14-inline-screen.tsv),
[summary/manifests](2026-10-29-mp3-round14-inline-screen.json),
[code generation](2026-10-29-mp3-round14-inline-screen-codegen.json),
[corpus check](2026-10-29-mp3-round14-inline-screen-corpus.json).

All four stages produce the same selected 13-fixture trace:
**662,735,590 bytes**, SHA-256
`878c81985e0638c5efe4a8b63e1f2873ca93952f2c7652c897f18edf7cb5f9ee`.
The 80-file comparison produces **687,503,590 bytes**, SHA-256
`6f95a67e0642aa4abbf34eb08750aa66d2ae4f4b490d5f0c62666f8552cf48a1`.
[Corpus commands, fixture hashes and matching outputs](2026-10-29-mp3-round14-corpus.json).

The trace retains 1,179,648 bounded Huffman result/cursor observations;
side-information, MPEG-1/LSF scalefactor, CRC and full-range requantization
checks; nonfinite Hybrid inputs at every coefficient; signed-zero/subnormal
history and reset checks; and complete file PCM. The existing Huffman tests
independently check every numeric codeword, signs, offsets, escape boundaries
and truncations, including all 4,096 quad configurations. The eight-bit peek
test adds complete two-byte pattern/bound coverage.

All 72 tests, strict all-target Clippy and crate formatting pass. Regeneration
from the original numeric huffcode file reproduces the tables, CSV and manifest
byte for byte. [Commands, logs, generation hashes, allocation observations and
source hashes](2026-10-29-mp3-round14-checks.json).
The measured speedups are specific to the recorded Windows x86-64/MSVC host
and compiler; the exact tests also run when the crate is tested elsewhere.
