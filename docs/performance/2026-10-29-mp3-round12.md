# MP3 decoder: twelfth optimization pass

The production baseline is `11af75a4d`. This pass retains empty-band
requantization skips and forced inlining of the pair and count1 Huffman decoders.
Only `src/spectral.rs` and `src/huffman.rs` change in production. All changes
use safe Rust; public signatures, coefficient/Huffman tables, generators and
resident decoder fields remain unchanged.

## Measurement method

The final stages are `round12-base`, `round12-band-only`,
`round12-pair-inline`, and `round12-final`, in that order. Each uses identical
probes, thirteen fixtures, compiler/configuration, bench profile and fixed Cargo
build path. The driver validates source, executable, helper and fixture hashes.
Seven fresh processes per stage rotate their order. Each process reports the
median of eleven measured batches after warmup using `QueryThreadCycleTime`,
pinned to Windows logical CPU 2. Compilation and correctness checks run outside
decision timings. Capture-time initial samples are not decision measurements.

The **184 workloads produce 5,152 final observations** in
[raw data](2026-10-29-mp3-round12.tsv) and
[manifests, medians, ranges and MAD](2026-10-29-mp3-round12.json). Requantization processes one
576-coefficient granule per operation. **Huffman operations decode 256 symbols**;
the pair-region quantizer probes decode a complete granule. Fixture construction
is untimed. CPU throughput below is the inverse cycle ratio; nanoseconds remain
in the raw data. No process observations or outliers are discarded.

All six heap counters are zero in all final observations and all 6,440 screen
observations. No heap-allocation reduction is claimed. The screen included
alternative LSF grouping and prefix-table experiments; it is a separate
measurement set and must not be pooled with final samples.

## 1. Skip zero requantization bands

The destination is already cleared before requantization. A long band or a
short-window band whose input coefficients are all zero can retain those
positive-zero outputs directly: `power(0, amplitude)` already returns positive
zero for every amplitude. The path skips per-band exponent/amplitude work and
redundant coefficient writes.

Short windows now borrow one contiguous input span and advance the source
position once, including when the span is skipped. A zip maps nonzero spans
into the same interleaved frequency positions. The global all-zero shortcut,
lazy power-cache initialization, shape validation and nonzero arithmetic retain
their behavior.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Long, only first coefficient | 1,499.40 | 1,324.24 | 11.7% | 1.132x |
| Long, only last coefficient | 1,553.62 | 1,557.35 | -0.2% | 0.998x |
| Pure short, only first coefficient | 2,696.56 | 1,344.88 | 50.1% | 2.005x |
| Pure short, only last coefficient | 2,900.47 | 1,484.04 | 48.8% | 1.954x |
| Mixed, only first coefficient | 2,634.44 | 1,332.37 | 49.4% | 1.977x |
| Mixed, only last coefficient | 2,452.25 | 1,447.38 | 41.0% | 1.694x |
| Pure short, common dense coefficients | 3,562.92 | 3,730.40 | -4.7% | 0.955x |
| Mixed, wide dense coefficients | 35,572.83 | 36,406.27 | -2.3% | 0.977x |

Sparse short cases use 41.0–50.1% fewer cycles. Long input with only its final
coefficient nonzero does not improve. Dense pure short regresses 4.7%, mixed
wide input 2.3%, and the unchanged global-zero long probe rises from 274.59 to
300.28 cycles. The full data retains these costs. The final combined common
long-coefficient median is 2,846.04 versus 2,509.11 at baseline (13.4% worse),
although the band-skip stage alone is effectively flat for that input.

## 2. Inline pair decoding into its callers

`#[inline(always)]` on `huffman::pair` removes the out-of-line call boundary in
the measured quantizer and direct-symbol loops. Its existing checked operations
and transactional cursor logic become visible to caller optimization. The
decoder algorithm and numeric trees are unchanged; no new lookup tables or
runtime initialization are introduced.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Book 13, mixed | 15,263.15 | 7,487.15 | 50.9% | 2.039x |
| Book 23, mixed | 15,594.16 | 7,760.20 | 50.2% | 2.010x |
| Book 13, zero pairs | 9,551.76 | 3,767.06 | 60.6% | 2.536x |
| Book 13, two negative fifteens | 32,642.06 | 24,474.47 | 25.0% | 1.334x |
| Full pair region, boundaries 0/0 | 17,579.97 | 9,037.03 | 48.6% | 1.945x |
| Full pair region, boundaries 15/7 | 15,093.48 | 7,103.68 | 52.9% | 2.125x |
| Uncoded book-zero region | 59.27 | 77.48 | -30.7% | 0.765x |

Mixed book-13/23 probes use about 50–51% fewer cycles. The complete pair-region
quantizer cases improve 48.6–52.9%. An uncoded book-zero region is a material
counterexample: 59.27 to 77.48 cycles, 30.7% worse, despite executing no pair
decoder. Its final combined median is 62.12 cycles. Code layout and caller
register allocation are not isolated by these comparisons.

## 3. Inline count1 decoding while retaining stuffing rollback

The same attribute on `huffman::quad` removes the remaining count1 call boundary.
The body and return contract stay unchanged. An incomplete word still leaves the
cursor at its pre-word position so `quantized` can treat it as stuffing.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Count1 A, mixed | 5,857.58 | 4,648.13 | 20.6% | 1.260x |
| Count1 B, mixed | 6,101.88 | 5,252.42 | 13.9% | 1.162x |
| Count1 A, all zero | 3,902.27 | 2,453.79 | 37.1% | 1.590x |
| Count1 B, all zero | 4,661.08 | 2,954.03 | 36.6% | 1.578x |
| Count1 A, four nonzeros | 7,369.71 | 6,640.09 | 9.9% | 1.110x |
| Count1 B, four nonzeros | 5,672.10 | 4,976.28 | 12.3% | 1.140x |

All ten count1 workloads improve at this stage, by 9.9–37.1%. Whole-file changes
versus pair-only are mixed: some become slightly slower. For example, 8 kHz mono
CBR rises from 2,993,211.50 to 3,123,485.00 cycles (4.4% worse); the pair-only
process MAD is 245,291.50 cycles. No general file-speed gain is attributed to
count1 inlining alone.

Pair and quad are no longer emitted standalone in the final benchmark, and the
quantizer's assembly contains no calls to either entry point. This is a measured
inlining result, not a claim about all future compilers or function-pointer uses.
The quantizer grows substantially because the decoding bodies are present in
its hot loops. Static counts are not retired instructions or whole-program
code-size measurements. Per-function stack reservations exclude callees and
return addresses; no peak-stack reduction is claimed.
[Assembly hashes, calls, counts and layout commands](2026-10-29-mp3-round12-codegen.json).

All stages retain the same measured layouts: FrameDecoder 51,568 bytes/alignment
16; ScaleFactors 136/8; Hybrid 4,608/8; Synthesis 8,208/16. No resident fields,
heap allocations or immutable tables are added by the retained changes.

## Rejected alternatives

The initial screen used `round12-base`, `round12-lsf`, `round12-bands`,
`round12-prefix`, and `round12-inline`. Its last two entries are alternative
Huffman changes from the preceding stage, not cumulative changes. Final timings
restore the original LSF implementation and measure band skips, pair inlining
and count1 inlining independently.

Width-dependent LSF chunks could fit more factors into each u32 read, but added
overhead in common cases. Normal long compression 359 rose from 203.32 to 250.43
cycles (23.2% worse), and pure-short intensity compression 359 from 256.24 to
303.13 (18.3% worse). The original fixed six-factor grouping is retained.

Extra five-bit heads for books 13 and 16–23 were exact and improved mixed
book-13/23 probes by about 16–17% versus their preceding stage. They also slowed
zero-pair patterns by 4–5% and added 24 net table bytes after pruning 22 nodes
and eight root slots. Pair inlining was substantially faster on the same inputs
and required only an attribute, so the new prefix tables and generator changes
are discarded. [Screen data](2026-10-29-mp3-round12-screen.tsv),
[summary/manifests](2026-10-29-mp3-round12-screen.json),
[code generation](2026-10-29-mp3-round12-screen-codegen.json),
[corpus check](2026-10-29-mp3-round12-screen-corpus.json).

A short-IMDCT transpose preserved every one of its 72 coefficient bit patterns,
but the expanded verifier detected different NaN payload/sign bits, beginning
at byte 177,840,780. It is rejected without relaxing the exact-output check.
The original DSP code, tables and generator are retained.
[Rejection hashes, bit-pattern example and regeneration audit](2026-10-29-mp3-round12-rejected-short.json).

## Exact behavior and validation

All **70 tests**, strict all-target Clippy, scoped formatting and whitespace
checks pass. The existing exhaustive Huffman tests cover every numeric codeword,
signs, escape boundaries, offsets, truncation and atomic cursor behavior.

The verifier adds **25,920 one-hot requantization cases**: every coefficient
position at all nine rates and five block shapes, with varied gains, signs and
scalefactors. Destinations start with distinct quiet NaNs so skipped/reordered
writes cannot silently leave stale data. It also adds **3,456 nonfinite hybrid
cases**, serializing both mutated input and output after combinations of
different NaN payloads and infinity at every position in six block layouts.
Existing dense, zero, bounded-bitstream, scalefactor, stereo, synthesis, CRC and
Huffman observations remain.

All four final stages produce an identical **634,419,430-byte trace** for
**80 files** (42 encoder, 36 seek and two protected CRC fixtures), SHA-256:

`eab107bc0ae3346563452b0bee930ff77162391406bbbcee16ce85527c622279`

The selected thirteen-file trace is 609,651,430 bytes with SHA-256
`e388e71bbcfa2f55a2adb67cc2cc973cb5e5eaf5829c7669d2f67414872b7663`.
Traces include kernel/error observations and PCM; expanded coverage changes
their size and hash from earlier passes.
[Corpus commands and fixture hashes](2026-10-29-mp3-round12-corpus.json).
[Validation output and source hashes](2026-10-29-mp3-round12-checks.json).

To repeat final timings using the saved immutable stages:

```text
python crates/deadlib-audio/decode/mp3/scripts/benchmark.py --stage round12-base --stage round12-band-only --stage round12-pair-inline --stage round12-final --runs 7 --output docs/performance/2026-10-29-mp3-round12.tsv
```

Snapshots and executables remain under ignored `target/mp3-perf-20261028` to
preserve the fixed build identity across the date rollover. Rebuilding elsewhere
requires capturing each production revision with identical committed probes,
compiler/configuration and recorded fixture hashes. Validation commands are
recorded in the checks artifact.
