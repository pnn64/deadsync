# MP3 decoder: fourth optimization pass

This pass retains fixed-size bit-field loads and direct skipping of zero-coded
Huffman regions. The production baseline is `450e07e7a`. No production unsafe
code, heap allocation, cache, lookup-table storage or public API changes are
introduced. The byte-extraction loop and repeated zero-pair decoding are
removed from their respective paths.

## Measurement method

Resident-input probes use the repository release/bench profiles, a fixed Cargo
package/build path, a pinned Windows thread and `QueryThreadCycleTime`, as in
[the previous pass](2026-10-28-mp3-round3.md). Each process reports eleven
measured-batch medians after warmup. Retained changes use seven process runs
with rotating binary order. Rejection screens explicitly identify three-run
results. CPU cycles, nanoseconds, six allocation counters, medians, MAD and
source/fixture/binary/compiler/configuration hashes are retained in TSV/JSON.

The final comparison has three builds with identical probes and ten files:
`round4b-base`, `fields-b-final`, and `region-zero-final`. All six allocation
counters are zero in all **1,008 observations**. Setup and initial capacity
warming are outside steady-state measurements.

## 1. Fixed-size bounded field loads

A 1-32-bit field intersects at most five bytes. The reader loads those bytes
with fixed-size integer cases, discards trailing padding bits and masks off
preceding bits. This replaces the variable-iteration extraction loop and its
per-byte cursor updates with one cursor update. It requires no padded input
and reads only bytes intersecting the field. Width validation still precedes
truncation validation, zero-width reads return zero, and failures preserve the
cursor. One-bit flags continue to use the existing `read(1)` path.

The following isolates the reader change; one operation reads **512 fields**.

| Width | Before cycles/op | After cycles/op | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| 1 bits | 4,532.68 | 4,528.51 | 0.1% | 1.001x |
| 4 bits | 4,859.29 | 4,520.60 | 7.0% | 1.075x |
| 9 bits | 8,287.44 | 4,737.91 | 42.8% | 1.749x |
| 16 bits | 8,298.86 | 4,938.53 | 40.5% | 1.680x |
| 24 bits | 11,092.87 | 5,361.07 | 51.7% | 2.069x |
| 32 bits | 13,430.55 | 4,419.85 | 67.1% | 3.039x |

The 9-32-bit cases improve by 40.5-67.1%; the one-bit case is effectively flat.
An earlier seven-run comparison with the rejected tighter synthesis masks also
shows large multi-byte gains; its complete counterexamples are retained in
[field observations](2026-10-28-mp3-fixed-fields.tsv) and
[field manifests](2026-10-28-mp3-fixed-fields.json). Final numbers above use the
committed synthesis layout throughout.

Independent tests compare every two-byte pattern and flag sequence against a
bitwise oracle. Additional tests cover lengths 0-40 bytes, every starting bit,
bounded tails, widths 0-33, mixed successive reads, validation priority,
remaining-bit counts and cursor atomicity.

## 2. Skip zero-coded Huffman regions directly

The output is already cleared before big-values decoding. Book zero emits
zero pairs and consumes no bits, so the decoder advances directly to the end
of a zero-coded region. This removes pair calls, pair copies and repeated zero
writes for that region. Region ends are computed once; nonzero books are
selected once per region rather than through two comparisons per pair.

Supported band boundaries and the big-values limit are even and ordered, so
each skipped end is exactly the next pair boundary. Unused invalid books are
still ignored; a used invalid book still errors. Count1 parsing follows the
same final big-values cursor, and granule errors remain cursor-atomic.

The following isolates this change after fixed-size field loads. Each
operation decodes a **288-pair big-values area**.

| Input | Before cycles/op | After cycles/op | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| All three regions use book zero | 2,619.07 | 52.68 | 98.0% | 49.717x |
| Only middle region uses book zero | 12,720.68 | 11,201.30 | 11.9% | 1.136x |

The all-zero case is a clear 49.7x targeted gain. The middle-zero result also
includes compiler/layout variation: an untouched hybrid/start probe shifts
from 10,747.60 to 9,078.96 cycles in the same comparison. Nonzero region probes
improve by 5.1-6.4%, comparable to some control shifts, so those are not claimed
as an independent broad Huffman speedup.

A normative book-1 test places zero regions before, between and after coded
pairs at all nine sample rates. It checks output clearing, exact coefficients,
bit consumption and big-values limits on both sides of region boundaries.

These are direct measurements of the final build against the original
baseline, rather than products of separate ratios. Each operation decodes a
complete resident file, including decoder reset.

Whole-file medians range from 10.9% fewer cycles to 6.2% more cycles. The VBR
file is effectively flat. Run-to-run variation and changes in untouched
controls are substantial; these observations do **not** establish a uniform
end-to-end speedup. The retained gains are specific to multi-byte field reads
and zero-coded regions. Both gains and regressions are kept in
[final observations](2026-10-28-mp3-round4-retained.tsv) and
[final manifests, medians and dispersion](2026-10-28-mp3-round4-retained.json).

## Rejected direct-flag experiment

Replacing `flag()` with a separate bit-mask path and using it for Huffman tree
transitions did not improve its target. A three-run rotating screen measured
1,640.11 to 1,695.42 cycles per 512 flags; the book-31 pair probe rose from
21,074.85 to 23,120.15 cycles per 256 pairs. These timings do not justify a separate flag path. The experiment passed all 55 tests and all-target
Clippy, but its production changes were reverted.

[Screen observations](2026-10-28-mp3-parser-screen.tsv),
[screen manifests and summary](2026-10-28-mp3-parser-screen.json). This was a
three-run rejection screen, rather than the seven-run retained-change gate.

## Rejected tighter window masks

Masking the two synthesis-window indices with 960 and 992 preserves their
reachable values. It removes two bounds-failure call sites and 50 static
assembly instructions (1,429 to 1,379), without unsafe code or additional data.
However, the first seven-run comparison changes synthesis from 1,473.46 to
1,453.97 cycles/slot, and the independent seven-run confirmation changes it
from 1,522.63 to 1,506.12. Each improves in only four of seven paired runs;
median paired reductions are 17.89 and 16.51 cycles. A three-run screen shows a
larger gain, but that evidence is weaker than the inconsistent seven-run
samples. The production mask changes were reverted.

## Rejected twelve-lane short transform

The first short-transform transpose accumulated twelve outputs together,
preserving all 72 coefficients and arithmetic order. It passed all 55 tests,
all-target Clippy and the extended output fingerprint. Nevertheless, the
seven-run comparison against `region-only-final` increases pure-short hybrid
cycles from 3,977.56 to 4,495.36 (13.0%), and the unchanged normal long shape
from 9,846.99 to 11,569.41 (17.5%). All ten file decodes regress in this paired
comparison. The twelve-lane implementation was rejected. A four-lane tiled
variant is measured separately.

[Four-build observations](2026-10-28-mp3-round4-final.tsv),
[four-build manifests and summary](2026-10-28-mp3-round4-final.json).

## Rejected four-lane short-transform tiles

The smaller `[3][6][4]` layout also preserves all 72 coefficient bits and the
six-term accumulation order, with the same 576 coefficient bytes. It passes
all 55 tests and all-target Clippy. A three-run rotating rejection screen
against `region-zero-final` increases pure-short hybrid cycles from 3,632.51
to 5,386.31 (48.3%) and normal long hybrid cycles from 9,067.98 to 11,903.27
(31.3%). All ten file decodes regress. The four-lane implementation, both
coefficient-generator experiments and their documentation changes are reverted.
