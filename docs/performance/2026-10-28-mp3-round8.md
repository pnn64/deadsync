# MP3 decoder: eighth optimization pass

The production baseline is `549592815`. This pass retains a complete book-1
code/sign lookup, a shared fixed-width prefix peek, and MPEG-1 zero-width
scalefactor shortcuts. All changes use safe Rust, with no public API changes,
heap allocation, runtime initialization or per-decoder fields.

## Measurement method and input coverage

Resident-input probes use the fixed Cargo package/build path, repository bench
profile, a pinned Windows thread and `QueryThreadCycleTime`. Seven fresh
processes per stage rotate their order. Each process reports the median of
eleven measured batches after warmup. Allocation counters measure one additional
operation after the timed batches. Packet/fixture construction stays outside
timing.

There are 133 workloads: the prior 107 plus eight bit-field widths and eighteen
MPEG-1 scalefactor cases. The MPEG-1 probes cover long, pure-short and mixed
blocks, compression 0/4/15, and granule-one SCFSI masks 0/5/15. Their previous
factors contain varied values and widths. **Bit-field operations read 512 fields;
Huffman operations decode 256 symbols; each scalefactor operation is one read.**
The ten whole-file and nine fresh-decoder probes remain.

The final comparison uses `round8-final-base`, `round8-fused-book1`,
`round8-fused-prefixes` and `round8-fused-final`. All stages use identical probes,
fixtures, compiler/configuration and profile. The initial screen used the same
workload labels but built the MPEG-1 header inside those timed closures. The
final comparison constructs it outside timing and rebuilds the baseline with
the corrected probes. Do not compare absolute scalefactor times between these
experiments. Capture-time initial samples are not decision measurements.

The verifier adds **31,104 MPEG-1 scalefactor result/cursor observations**:
two data patterns, all sixteen compressions, three shapes, two granules,
three SCFSI masks, three previous-factor states, nine bounds and two part2_3
limits. Reads start at bit five. Cases include absent/short-block predecessors,
zero-bit limits, nonzero preflag and varied reused values/widths. The expanded
trace cannot be compared directly with earlier passes' hashes.

The seven-run comparison retains **3,724 observations** in
[raw data](2026-10-28-mp3-round8.tsv) and
[manifests, dispersion and summary](2026-10-28-mp3-round8.json).
All six allocation counters are zero in these observations and all 1,596
initial-screen observations. No allocation reduction is claimed in this pass.

## 1. Decode the entire small book-1 word in one lookup

Book 1 has magnitudes zero or one and no escape extensions. Its complete code
and zero, one or two sign bits fit in five bits. A 32-entry packed `u32` table
stores the two signed output bytes and total consumed length. One prefix peek,
lookup and checked skip replace the tree walk, magnitude unpacking, linbits
lookup and individual sign reads. Casting the two signed bytes to i16 preserves
all outputs.

The generator derives the complete signed words from the unchanged numeric CSV
source, rejects overlapping/incomplete prefixes and verifies the five-bit bound.
The old three-node tree is pruned. A 128-byte lookup replaces twelve node bytes:
**116 additional table bytes** overall. The final forest contains 1,334 reachable
nodes and all immutable table elements total **6,352 bytes**, versus 6,236 at
baseline. No decoder-state or heap storage is added.
[Table/bound audit and regeneration hashes](2026-10-28-mp3-round8-tables.json).

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Book 1, mixed input | 11,912.92 | 9,292.53 | 22.0% | 1.282x |
| Book 1, zero pairs | 9,839.53 | 8,844.09 | 10.1% | 1.113x |
| Book 1, two negative nonzeros | 14,064.68 | 8,946.38 | 36.4% | 1.572x |
| Book 13 control | 14,332.03 | 15,746.71 | -9.9% | 0.910x |
| Book 31 control | 17,040.88 | 18,424.17 | -8.1% | 0.925x |

The small-book gains are substantial. The other-book controls use 8-10% more
cycles at this stage despite retaining their tree algorithms. Table placement,
code layout and the new dispatch branch are not isolated by this comparison.
The final combined book-31 median is close to baseline; the book-13 control
remains about 9% slower. These counterexamples remain in the full data.

## 2. Reuse a bounded five-bit peek

The internal immutable peek loads one byte when the five bits fit, otherwise
one big-endian two-byte word. With fewer than five available bits, it reads only
physically available bytes and clears the unavailable low bits. Empty input
returns a padded zero prefix. The caller still checks the selected entry's
actual consumed length; padding never makes an incomplete word successful.

The book-1 stage introduces this primitive. This stage also routes the existing
escape-family and count1-A lookups through it, removing copied lookahead cursors,
generic field extraction and intermediate Result handling. The peek returns an
index bounded by 31. The general `BitReader::read` and `flag` method bodies stay
identical to baseline.

The helper is checked independently against bit-by-bit extraction for every
two-byte value, every offset, and every bound up to five bits, plus empty input:
**5,701,633 pattern/bound cases**. Position and remaining length stay unchanged.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Book 31, mixed input | 18,424.17 | 17,141.41 | 7.0% | 1.075x |
| Count1 A, mixed input | 6,874.96 | 6,118.78 | 11.0% | 1.124x |
| Count1 A, four nonzeros | 8,551.06 | 7,441.49 | 13.0% | 1.149x |
| Unchanged book-1 control | 9,292.53 | 9,478.01 | -2.0% | 0.980x |
| Unchanged 32-bit reader control | 4,667.67 | 4,621.13 | 1.0% | 1.010x |

The mixed count1-A and escape-family benefits are clear. The book-1 decoder
already used the helper in the preceding stage, so its small change is a
control rather than evidence of another algorithmic gain.

## 3. Skip MPEG-1 zero-width scalefactor partitions

An all-zero MPEG-1 width plan returns the already-defaulted factors when there
is no SCFSI reuse. Long granule-one reuse still checks/copies its predecessor
in the original order, including missing/short predecessor errors. Individual
zero-width fresh groups are skipped. Short-block fields are read in two
partitions, removing repeated per-band width selection and skipping empty
partitions. Mixed low long bands also skip zero-width reads.

This removes zero-bit reader calls and redundant writes from the executed path;
nonzero fields keep their original wire order. Preflag, block-shape flags,
encoded-bit counts, output widths and failure cursor atomicity remain exact.
The extended MPEG-1 tests check values and widths for every compression/shape,
and all sixteen SCFSI masks for compressions 0/4/15 with varied previous widths.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Zero widths, long | 117.83 | 70.13 | 40.5% | 1.680x |
| Zero widths, pure short | 133.52 | 73.05 | 45.3% | 1.828x |
| Zero widths, mixed | 169.72 | 70.24 | 58.6% | 2.416x |
| Partial zero widths, pure short | 253.32 | 204.27 | 19.4% | 1.240x |
| All nonzero widths, pure short | 415.32 | 333.05 | 19.8% | 1.247x |
| All nonzero widths, long control | 263.73 | 271.37 | -2.9% | 0.972x |
| Zero widths, full SCFSI reuse control | 93.07 | 92.06 | 1.1% | 1.011x |

Zero-width cases gain 1.68-2.42x in this incremental comparison. Partitioning
also helps the all-nonzero short-block case by avoiding per-band width
selection. The all-nonzero long control is 2.9% slower; full SCFSI reuse is
nearly flat. Those differences overlap observed variation and do not establish
a general improvement for every scalefactor configuration.

## Rejected general reader rewrite

A single-byte shortcut plus a general read inlining hint helped small fields
but harmed entropy decoding in a three-run rotating screen. Eight-bit batches
changed from 4,677.33 to 4,148.77 cycles, while 32-bit batches rose from 4,685.67
to 5,061.89. Mixed book-31 decoding rose from 17,374.52 to 23,394.75 cycles
(+34.7%), and count1-A from 6,839.40 to 13,373.04 (+95.5%). The rewrite was
reverted. Its four stages, 1,596 observations and hashes remain in
[screen data](2026-10-28-mp3-round8-screen.tsv) and
[screen summary/manifests](2026-10-28-mp3-round8-screen.json).

A direct flag getter gave no clear first-sample benefit and was not retained.
A branch-based book-1 decoder caused the compiler to emit flag-getter calls;
forcing their inlining did not show a convincing initial dense-input gain. Those diagnostics motivated the complete code/sign lookup.
No performance conclusion is based solely on their capture-time samples.

## Generated code and storage

The standalone pair function's stack reservation falls from 96 to 88 bytes.
Its static instruction count rises from 292 to 387 for the complete book-1
lookup, then to 413 with shared prefix loading. The quad function changes from
199 instructions / 40 stack bytes to 227 / 32. These larger straight-line
bodies replace repeated reads, cursor copies and intermediate result handling;
static instruction counts alone do not predict their measured runtime.

The rejected branch-based prototype has six static flag-getter calls in its
pair body; the retained pair body has none. The saved benchmark image shrinks
from 592,384 to 590,848 bytes, including linked production/probe code and linker
padding. This is not an application-binary size measurement.

The scalefactor function changes from **2,628 to 2,172 static instructions**;
its stack reservation rises from **376 to 408 bytes**. The partitioned short
path has a stack tradeoff despite its lower cycle counts. The prefix helper is
not emitted as a standalone function in the retained builds. These are counts
of extracted standalone bodies, excluding helpers/initializers, and are not
retired-instruction measurements or whole-decoder stack bounds.
