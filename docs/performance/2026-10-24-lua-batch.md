# Reuse native callback compilation and byte storage

Baseline: `838e92144c937bb795c6e671f1fe210d9ebf08e3` (0.5.2362). Result: 0.5.2363. New stage executables were measured at 0.5.2362. Baseline executables are the preceding pass’s final normal-library binaries, built at 0.5.2361 with the identical baseline implementation and harness; its final version bump was metadata only. Adjacent JSON preserves source/binary hashes, raw samples, throughput, allocation/reallocation counts, requested bytes, retained payloads, authored traces, native end states and focused check receipts.

## Retained changes

1. `deadlib-lua-legacy::program::Compiler::batch` offers bounded loading-time reuse of the last successful compilation under a fixed immutable schema. Exact dump bytes, argument/upvalue bindings, numeric bits, byte contents, object/cell/input identities and input type contracts must match. Errors do not replace the last success. The cache owns Rust data only; the ordinary immutable Compiler API retains Send/Sync. DeadSync uses a fresh batch for each schema attempt when there are at least eight callbacks. Callback order, execution count, explicit shared cell identities and readonly-to-mutable retry remain intact.

2. Generic group string normalization builds a mapping once per distinct input Code Arc. Repeated handles reuse the existing rewritten Code. Normalization still deduplicates byte contents within and across pools, including pools that contain duplicate literal bytes. This removes unused mapping vectors and repeated hashing; unique pools pay a slightly larger mapping entry.

3. Generic lowering moves already-owned prototype constants into the program arena before initializing byte cells. A cell whose initial bytes equal a prototype literal reuses that storage, avoiding a clone. Searches are bounded to the prototype prefix; the existing previous-initial-index shortcut remains. Mutable cell slots remain separate. Unmatched initial bytes are cloned as before.

Generic mechanisms remain in deadlib-lua-legacy; callback schemas, retry policy, ordering and rendering fixtures remain in deadsync-song-lua. No theme or noteskin policy moved, and no production unsafe code was added. The accepted authored language is unchanged. The new repeated string-state callback fixture exercises writable-state retry and all three changes together.

## Measurement

Release, locked dependencies, LTO disabled, two build jobs, logical CPU 2 affinity. Timing processes run serially, outside compilation. Rust GlobalAlloc metrics cover all process threads, including mlua allocations routed through it, and exclude native malloc. Requested bytes are cumulative requests, including reallocations, not peak memory.

For each of six authored fixtures and each individual/combined comparison: three alternating process pairs; ten native samples, first discarded; 393,216 actual input/update pairs per sample, or 49,152 for both 16-callback fanouts. Every process first compares 96 authored Lua/native input and update steps and preparation outputs. It drops the original Scene/artifact, loads a separately finalized VM, compiles and drops that VM, asserts finalization, replays the authored trace, then times only the detached native owner. All long-run handling digests, scalar bits and full actor end states match. Preparation uses ten batches of 128, first discarded.

## Validation and limits

58 focused checks passed: SDK program tests, actor inputs, compiled inputs, actor method semantics/names and the ignored production OpenGL differential. The new SDK regression compares ordinary and batch compilation for argument/capture bindings with signed zero, NaN payloads, binary bytes, object identities, cell/input indices, nullable contracts, malformed bytes and upvalue errors. Programs outlive compiler/schema/dumps; separate machines from a cache hit mutate independently after the loading VM is gone. Existing checks cover cell aliasing, byte-copy semantics, nil registers, malformed chunks, receiver identity, errors, fallback and scheduling.

The production render differential compares 240 complete RenderFrame structures and 240 pixel buffers across eight authored fixtures. Six ordinary Scene fixtures compare six update/input/draw frames each. All 144 retained-stage gameplay processes prove VM finalization and compare traces and long-run end states. Runtime inputs remain actual data; no action timeline is precomputed.

The default Scene still retains Lua; detached compiled snapshots do not establish whole-scene VM removal. General loops/calls, queued/effect-owned behavior and other unsupported cases retain existing fallback. The cache is last-request-only and does not improve distinct bodies/bindings; it adds key storage on misses. It is enabled in Game only at the existing eight-callback density boundary. No cross-theme matrix or full Song --lib/full suite was run, and the historical six Song failures were not re-audited. Complete-loading and native timing regressions remain visible in the tables.
