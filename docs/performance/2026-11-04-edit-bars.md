# Edit bar counting and signature scans — 2026-11-04

Baseline: `c3946aad58d02096c11465f11dd63a160752fb42`. Three safe Rust changes in `measure_lines.rs` remove arithmetic and repeated signature work:

1. Segment counts combine two positive integer quotients into one period quotient. Spans shorter than one period return one without division.
2. Cursor movement counts from its existing cached start row, step and frequency. It no longer reloads and validates the current signature or repeats row conversion for that count; backward movement also drops a duplicate signature lookup.
3. Candidate-step scanning returns as soon as its running GCD reaches one. Remaining signatures cannot reduce it further.

One private method holds the shared count formula. Cursor/cache fields, public interfaces, row rounding, returned frames, measure indices and update order remain unchanged. There are no new dependencies, state fields, heap allocations or unsafe blocks. The GCD implementation itself was restored after a narrower variant showed no useful gain.

## Exact arithmetic and cache reuse

For `D = end_row - start_row > 0`, the original count is `floor(floor((D - 1) / step) / frequency) + 1`. Both divisors are positive. This equals `floor((D - 1) / (step * frequency)) + 1`. Validated `step` is at most `i32::MAX / 4`; validated frequency is at most `i32::MAX`, so their product is positive and below `2^60`. The signed row difference is widened before subtraction and fits i64. Returning one when `D - 1 < period` is exactly the zero-quotient case. The original early return for `end_row <= start_row` remains.

The cursor's existing constructor already derives its cached step/frequency from the same validated signature. Its timing slice is immutably borrowed, and segment changes replace that cache. Using those fields therefore gives the same count as reloading the signature. Prefix additions/subtractions occur in their original order, and no cache fields are added. Tests compare cursor size with the frozen original.

GCD results are at least one. Once a running result is one, every later GCD is also one, including signed row limits. Remaining validation and row-conversion helpers are pure and cannot change the result. Empty/default-signature handling remains unchanged.
