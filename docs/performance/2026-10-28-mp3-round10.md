# MP3 decoder: tenth optimization pass

The production baseline is `7ff1267de`. This pass batches adjacent scalefactor
fields into checked u32 reads in three separately measured stages: MPEG-1 short
windows, MPEG-1 long groups, and MPEG-2/2.5 LSF partitions. Only
`src/scalefactors.rs` changes in production. All code is safe Rust; public APIs,
coefficient tables and decoder state are unchanged.

## Measurement method

The stages are `round10-base`, `round10-short`, `round10-long`, and
`round10-lsf`. Each uses identical committed probes, 13 fixture hashes, compiler,
configuration, bench profile and fixed Cargo build path. The driver checks
saved source and executable hashes before comparing stages. Seven fresh
processes per stage rotate their order. Each process reports a median of eleven
measured batches after warmup, pinned to Windows logical CPU 2, using
`QueryThreadCycleTime`. Compilation and correctness checks run outside decision
timings. Capture-time initial samples are not decision measurements.

The **166 workloads yield 4,648 observations**, with CPU cycles and nanoseconds,
in [raw data](2026-10-28-mp3-round10.tsv) and
[manifests, medians, ranges and MAD](2026-10-28-mp3-round10.json). The probes add compression 5
to MPEG-1 cases and compression 359 to LSF cases. The latter exercises intensity
widths `[4, 5, 5, 0]`. Each scalefactor operation reads one granule/channel;
fixture/header construction is untimed. CPU throughput below is the inverse
cycle ratio. All six heap counters are zero in every observation; no allocation
reduction is claimed. All process observations, including outliers, are retained.

## 1. Read three MPEG-1 short-window factors together

All three windows in a short scalefactor band share one width. One read of
`3 * width` bits now replaces three field reads. Shifts and masks extract the
three values, and one array assignment records their common widths. The largest
combined field is twelve bits. A pure-short block with both widths nonzero needs
twelve field reads rather than 36. Existing zero-width partition skips remain.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Pure short, compression 4 | 221.67 | 157.14 | 29.1% | 1.411x |
| Pure short, compression 5 | 328.06 | 267.81 | 18.4% | 1.225x |
| Pure short, compression 15 | 340.69 | 267.59 | 21.5% | 1.273x |
| Mixed, compression 15 | 407.79 | 324.38 | 20.5% | 1.257x |

This first stage also slows unchanged nonzero LSF controls by roughly 10–21%.
For example, normal long compression 359 rises from 266.01 to 321.48 cycles.
The following stage returns it to 272.75, and the final stage reaches 219.13.
The algorithm for LSF is untouched at the first two stages; layout, register
allocation and inlining effects are not isolated. These counterexamples remain
in the raw four-stage results.

## 2. Read complete fresh MPEG-1 long groups

A fresh SCFSI group has five or six equal-width values, with widths at most
four: the complete word fits in 24 bits. One checked read followed by reverse
mask/shift extraction replaces the per-band field-reading loop. Width metadata
is filled once per group. The eight long factors of a mixed MPEG-1 block also
fit in one word, at most 32 bits. Fully fresh long blocks use four reads rather
than 21; the mixed long prefix uses one rather than eight.

The private `read_values` helper performs this exact packed-word operation.
SCFSI reuse still copies the predecessor's values and widths, with the same
missing/short-predecessor checks in the same group order.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Long, compression 4 | 164.89 | 112.91 | 31.5% | 1.460x |
| Long, compression 5 | 276.72 | 155.08 | 44.0% | 1.784x |
| Long, compression 15 | 277.51 | 157.40 | 43.3% | 1.763x |
| Long, granule 1, compression 15, SCFSI mask 5 | 176.52 | 124.30 | 29.6% | 1.420x |
| Mixed, compression 15 | 324.38 | 219.50 | 32.3% | 1.478x |

Pure-short cases also improve at this stage despite unchanged short-window
logic: compression 15 moves from 267.59 to 221.80 cycles. The large reduction
in generated reader code is relevant evidence, but does not isolate a single
cause for this cross-path change.

## 3. Batch each LSF partition in chunks of six

LSF partitions may contain eighteen equal-width factors. Nonzero partitions
now pass chunks of at most six to the same packed-word helper. Valid LSF widths
are at most five, so each read contains at most thirty bits. Width metadata is
filled once per partition. This removes the per-value bit-reader call and width
store; zero-width skips and the existing long/short/mixed destination mapping
remain. A full eighteen-value partition needs three reads rather than eighteen.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Long, normal, compression 399 | 278.00 | 216.93 | 22.0% | 1.282x |
| Pure short, normal, compression 511 | 466.22 | 305.98 | 34.4% | 1.524x |
| Pure short, intensity, compression 359 | 471.31 | 328.64 | 30.3% | 1.434x |
| Mixed, normal, compression 511 | 435.38 | 293.23 | 32.6% | 1.485x |
| Mixed, intensity, compression 399 | 260.70 | 224.94 | 13.7% | 1.159x |

Across all measured nonzero LSF cases this stage reduces cycles by 13.7–34.4%.
Unchanged controls still vary: granule-one MPEG-1 long compression 5 with full
SCFSI reuse rises from 79.68 to 92.54 cycles at this stage, a 16.1% regression.
Its baseline median is 94.08. No claim is made that unrelated paths improve at
every intermediate stage.

These are static standalone function-body counts, not retired instructions.
The final reader plus helper contain 1,185 instructions versus 2,172 at baseline
(45.4% fewer). The compiler leaves the 65-instruction helper out of line despite
the ordinary inline hint; its call cost is included in the timings. Stack
reservations are per function and exclude callee/return-address use; no peak
call-chain stack reduction is claimed.

At every stage `FrameDecoder` measures **51,568 bytes, alignment 16**, and
`ScaleFactors` measures **136 bytes, alignment 8**, with this compiler/target.
No heap or resident decoder storage is added.

## Exact behavior and validation

The existing transactional outer cursor still commits only after complete
success. Packing never accepts unavailable fields: any incomplete packed word
fails, and all preceding local reads are discarded as before. Width-zero early
returns, part2_3-length errors, previous-factor metadata, signed coefficients
and floating-point operations retain their behavior. The helper's maximum word
length follows from its callers: eight times four bits for MPEG-1, six times
five for LSF. The public bit reader and its width/error checks are unchanged.

All **68 tests**, strict all-target Clippy, scoped formatting and whitespace
checks pass. The MPEG-1 success test now also checks every prefix length at
all eight bit offsets for every compression and block shape: **21,728 bounded
cases**, covering successful values and exact truncated-input/cursor behavior.
It passed against the baseline before production edits. Existing tests check
all sixteen SCFSI masks and all 512 LSF compressions, shapes, intensity modes,
varied encoded values, and both LSF MPEG versions.

The byte verifier adds **370,080 LSF observations**: two byte patterns, all 512
valid plus two invalid compressions, three shapes, normal/intensity modes,
three starting offsets, ten bit bounds and two part2_3 limits. Each serializes
the full result or exact error, cursor position and remaining bits. The existing
MPEG-1 bounds, full-domain requantization, stereo, hybrid, synthesis, CRC and
Huffman traces also remain.

All four stages produce the same **453,310,950-byte trace** for **80 files**
(42 encoder, 36 seek and two protected CRC fixtures), SHA-256:

`e6d34f29c46c7acf41078f7c7683e24197017b0bb5102e7f47564523c1a0c818`

The selected 13-file trace is 428,542,950 bytes with SHA-256
`a3452534e4183386fcf686a07c457b92858cb2defa334fca7cf92648f4fb3cf9`.
