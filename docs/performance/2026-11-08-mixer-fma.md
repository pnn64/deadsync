The centered SFX mixer now uses runtime-selected hardware FMA for general gains on supported x86/x86-64 CPUs. The existing exact-product fast path returns before the feature check. This removes one CRT `fmaf` call per sample at gains such as the application's default approximately 0.9, while retaining fused rounding and the portable fallback.

The production change is confined to `deadlib-audio-core`: one guarded dispatch and a private `mixer::fma` module. The crate's `forbid(unsafe_code)` becomes `deny(unsafe_code)` with a scoped exception for that module. Its only unsafe operation is the CPU-specialized call, guarded by Rust's CPU/OS feature detector. The specialized loop uses ordinary slices and `mul_add`; there is no inline assembly, manual SIMD intrinsic, unchecked indexing, new dependency or allocation. Panned mixing is unchanged.

On this machine, the measured public mixer call at 1,024 interleaved samples and the default gain improves **7.22× with one voice**, **8.66× with eight voices**, and **9.52× with 32 voices**. Those correspond to approximately **86%, 88% and 89% less CPU cost** for these workloads. Complete audio-callback time, audio latency, frame rate and application-wide performance are unmeasured.
