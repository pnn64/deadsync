# Network text and version labels, 2026-11-04

Three retained optimizations in `deadsync-net` and `deadsync-version`, starting
at `bda7ac85e` on isolated branch `perf/non-lua-kernels-20261104`. Lua crates
and the main worktree's existing changes are outside this batch.

## Changes and behavior

1. `log_body_snippet` returns immediately when its UTF-8 byte length is at most
   256. Longer bodies with an ASCII first 256 bytes truncate directly at that
   boundary. Other bodies use the original character-index traversal. This
   still returns the first 256 Unicode scalar values, preserves the owned
   buffer and capacity, and handles a multibyte character crossing byte 256.
2. `is_timeout_message` checks the shared `time` prefix once, using a safe
   four-byte load and ASCII case-folding mask. It then compares only `out` or
   `d out`. The existing `memchr2` candidate search remains. Truncation,
   overlapping candidates, arbitrary Unicode and the exact single space in
   `timed out` retain the original matching rules.
3. `user_agent` and `current_tag` copy a compile-time product/version literal
   when no valid override is present. They avoid parsing Cargo's version and
   formatting it back to text. A shared private helper reads the override fresh
   once per public call. Valid overrides still use semver parsing/formatting;
   empty, whitespace, invalid and non-Unicode overrides preserve their existing
   fallback and warning behavior. `current()` still returns a parsed `Version`.

All production changes use safe Rust. The two source files add 39 and remove
59 lines, including 46 lines of environment-mutating unit tests replaced by
child-process tests. Six test-only unsafe environment mutations and their
global lock are removed. The new benchmark and differential-test files are
additional verification code.

including the environment lookup. Default tag reallocations fall from two
to zero per call. Per-256 allocation totals are:

| Default label | Allocations before/after | Reallocations before/after | Allocated bytes before/after |

peak remains 52 bytes for these default-label batches. Valid-override and
parsed-version allocation counts and byte churn are unchanged.

Unicode fallback performs an extra ASCII-prefix check. The long-Unicode paired
measurement costs 1.8% more cycles; its unchanged-source control costs 2.3%
more, so this small overhead cannot be isolated precisely. No gain is claimed
for Unicode snippets, parsed versions or valid overrides. All five runs improve short/ASCII snippets, timeout matches and
default labels. Paired throughput ranges across runs are:

- Snippet, short ASCII: 8.399-8.627x.
- Snippet, long ASCII: 4.987-6.207x.
- Timeout, matches: 1.287-1.294x.
- User agent, default: 1.329-1.355x.
- Version tag, default: 1.784-1.805x.

## Evidence and reproduction

Adjacent TSVs and JSON manifests record each stage:

- `baseline`: unchanged production functions, with longer initial batches.
- `snippet`: the short-body and ASCII-prefix fast paths.
- `timeout`: the shared prefix check, retaining the snippet change.
- `version`: direct default labels, retaining both network changes.
- `control`: exact pre-batch production sources with the initial short harness.
- `control-aligned`: the same sources with frozen inline attributes matched.
- `control-wrappers`: the same sources and the final benchmark call boundaries.
- `final`: all three changes, five process runs.
- `debug`: correctness in the unoptimized profile.

Each manifest includes exact source, executable and correctness-log SHA-256
hashes, Rust/LLVM versions, CPU identifier, dependency lockfile, workspace
profile and command. Sources, binaries and raw logs are archived at
`D:\deadsync-net-text-20261104` on the measurement machine. The tracked script
rebuilds those artifacts independently from the checked-in sources.

The small workspace contains the exact two crates and their dependencies.
It avoids unrelated root-workspace platform dependencies and uses the root
Cargo package version. It performs no HTTP requests. Release builds use
optimization level 3, LTO, no incremental compilation and the repository's
static MSVC runtime flag. The baseline used 3,000 net and 2,000 version batches
per sample; all later stages use 300 and 200 respectively. Compare paired
ratios within each process; absolute cycles vary between stages.

The final harness calls both variants through equivalent non-inlined wrappers
and black-boxed function pointers. Unchanged-source controls still show
context/load sensitivity: `control-wrappers` has a 0.940x nonmatch ratio and
1.123x/1.130x ASCII/short-snippet ratios despite identical logic. Its matching
timeout, dense-candidate, default-agent and default-tag ratios are 0.994x,
0.997x, 0.977x and 0.995x. These controls limit the precision of the measured
speedups; small percentage changes are not conclusive. The retained target
improvements substantially exceed the corresponding control differences.

Each process pins its benchmark thread to CPU 2, alternates original/current
implementations for 12 rounds, discards the warmup and reports the median of
11 `QueryThreadCycleTime` samples. Every batch contains 256 calls. Fixture
generation and allocation counting stay outside timing. Snippet timing
recycles an owned buffer, including the same input-copy work for both variants;
this measures truncation without fixture allocation. Version calls include
environment lookup and returned-string allocation/destruction. A thread-local
counted system allocator records allocation/reallocation/free counts and byte
churn. Timed processes have no logger installed, so invalid-override timings
exclude warning emission. No whole-application or network-latency improvement
is claimed.

## Correctness

All 21 top-level tests pass in release and debug, including ten child-process
override cases on Windows. Frozen differential checks cover all ASCII case
patterns for both timeout phrases, ASCII-byte mutations, Unicode substitutions,
overlaps and truncation; snippet boundaries, combining sequences, control
characters and multibyte input; and exact version text and warning messages.
Child processes cover absent, empty, whitespace, invalid, uppercase-prefix,
leading-zero, valid, padded, prerelease/build and non-Unicode overrides without
mutating the parent's environment. The original source's four environment
tests are replaced by this richer subprocess coverage, so the unchanged-source
control has 25 top-level tests instead of 21.

Clippy passes for both crates and all targets with warnings denied. Changed
Rust files pass rustfmt, the Python runner compiles, and `git diff --check`
passes. The adjacent `net-text-checks.json` records the checks and log hashes;
all archived source, executable and correctness-log hashes were verified,
and final/debug hashes match the measured working-tree files. Those sources
also match the staged implementation after Git newline normalization.
