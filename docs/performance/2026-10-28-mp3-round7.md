# MP3 decoder: seventh optimization pass

This pass retains three safe Huffman changes: select signed quadruples directly,
resolve count1-A suffixes with a small lookup, and use a shared prefix lookup
for escape books 24-31. The production baseline is `6004ce8cc`. All public
results, errors and cursor boundaries are preserved. No production unsafe
code, runtime initialization or per-decoder fields are introduced.

The clearest CPU gains are in entropy kernels. The final whole-file comparison
has modest gains on nine of ten inputs; variation and counterexamples are
reported below. No universal decoder speedup is claimed.

## Measurement and coverage

The fixed Cargo package/build path, repository bench profile, pinned Windows
thread and `QueryThreadCycleTime` protocol follow the preceding passes. Each
process reports the median of eleven measured batches after warmup. Seven fresh
processes per stage rotate their order. Fixture loading, packet construction
and encoded-pattern preparation are outside timing. **Every Huffman operation
below decodes 256 symbols**, not one symbol. Allocation counters measure one
additional operation after the timed batches.

Eighteen new probes cover zero and maximum pair values in books 1/7/13/23/31,
and count1 masks 0/1/5/15 in both books. Setup verifies their decoded values and
exact consumed lengths. The ten resident whole-file and nine fresh-decoder
probes remain. All stages use the same 107 workloads and expanded verifier.

The first comparison includes `round7-base`, `quad-sign-table`,
`round7-count1-direct`, `round7-pair-prefix` and `round7-pair-head-final`.
The last two are rejected broad pair-prefix variants. Its **3,745 observations**
are retained in [raw data](2026-10-28-mp3-round7.tsv) and
[manifests, dispersion and summary](2026-10-28-mp3-round7.json).

A second seven-run comparison tests the focused escape lookup before an
inlining refinement: `round7-base`, `round7-count1-direct`,
`round7-escape-prefix`. Its **2,247 observations** remain in
[raw data](2026-10-28-mp3-round7-final.tsv) and
[manifests and summary](2026-10-28-mp3-round7-final.json).

The final seven-run comparison includes `round7-base`, `round7-count1-direct`,
`round7-escape-prefix` and `round7-escape-inline`. Its **2,996 observations**
measure the refined pair path and the combined whole-file result in one window:
[raw data](2026-10-28-mp3-round7-inline.tsv),
[manifests, dispersion and summary](2026-10-28-mp3-round7-inline.json).
The first two incremental changes below use the first comparison; the third
and combined whole-file results use this final comparison. Absolute cycle
levels differ across windows and must not be compared between them.

All six allocation counters are zero in all **8,988 formal observations** and
all **963 initial-screen observations**. Capture-time initial logs are excluded
from the reported comparisons.

## 1. Select the signed quadruple directly

The four-value magnitude mask determines a sign count and record offset.
One sign-field read selects an eight-byte `[i16; 4]` record, replacing four
conditional sign reads and output reconstruction. The generator emits exactly
81 records, one for each possible signed quadruple, plus sixteen packed layout
entries. These add **680 immutable bytes**. No popcount is executed at runtime.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Table B, mixed input | 5,644.22 | 5,074.40 | 10.1% | 1.112x |
| Table B, four nonzeros | 7,020.93 | 5,048.50 | 28.1% | 1.391x |
| Table B, two nonzeros | 5,505.72 | 5,167.25 | 6.1% | 1.066x |
| Table B, one nonzero | 4,870.70 | 5,182.84 | -6.4% | 0.940x |
| Table A, one nonzero | 7,377.61 | 8,871.97 | -20.3% | 0.832x |
| Table A, two nonzeros | 10,125.75 | 11,707.91 | -15.6% | 0.865x |

The dense table-B benefit is clear, but sparse table-A probes regress at this
stage. The next retained change recovers those table-A cases. A table-B
single-nonzero cost remains small in the combined result; the full data include
all zero, sparse and dense controls.

## 2. Resolve count1-A suffixes without a tree walk

The all-zero quadruple is the one-bit code `1`. Other codes start with `0` and
have at most five remaining bits. A 32-entry lookup stores the magnitude mask
and actual suffix length. A short tail peeks only available bits and zero-pads
the index; consuming the stored length still checks that the code is complete.
The outer copied cursor preserves failure atomicity.

This removes fifteen tree nodes (60 bytes) and the count1 root (2 bytes), while
adding a 64-byte lookup: **two additional bytes overall**. No per-bit tree
traversal remains for table A.

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Table A, mixed input | 6,626.70 | 5,483.33 | 17.3% | 1.209x |
| Table A, one nonzero | 8,871.97 | 6,749.19 | 23.9% | 1.315x |
| Table A, two nonzeros | 11,707.91 | 6,856.52 | 41.4% | 1.708x |
| Table A, four nonzeros | 11,485.34 | 6,671.26 | 41.9% | 1.722x |
| Table A, zero | 3,819.30 | 3,767.28 | 1.4% | 1.014x |
| Unchanged table-B mixed control | 5,074.40 | 5,081.65 | -0.1% | 0.999x |

The sparse/dense table-A gain is substantial; the zero case is close to a tie.
The unchanged table-B mixed control is nearly flat in this incremental run.

## 3. Share a prefix lookup across escape books 24-31

These books share the numeric codebook and differ in escape-field widths.
A five-bit lookup resolves short words directly or names the residual tree
node. Longer words continue with the existing bit walk. Other books keep their
previous tree algorithm. The public pair routine dispatches to this lookup
only after its unchanged zero/reserved-book checks.

The generator prunes 26 unreachable parent nodes (104 bytes), removes eight
unused root entries (16 bytes), and adds one shared 32-entry prefix table
(64 bytes). This change therefore **removes 56 table bytes**. The final forest
has 1,337 nodes; all retained roots and residual nodes are reachable.

The initial focused lookup caused the compiler to outline the small tree
walker. A private `inline(always)` annotation restores its previous inlining
and removes the additional helper call. The complete retained pair change is:

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Book 31, mixed input | 20,880.16 | 16,933.33 | 18.9% | 1.233x |
| Book 31, zero pairs | 12,916.48 | 11,328.83 | 12.3% | 1.140x |
| Book 31, maximum escaped pairs | 21,495.42 | 20,923.62 | 2.7% | 1.027x |
| Book 1 nonzero control | 14,206.70 | 13,932.10 | 1.9% | 1.020x |
| Book 13 mixed control | 13,658.17 | 14,187.16 | -3.9% | 0.963x |
| Unchanged 32-bit reader control | 4,616.96 | 4,549.36 | 1.5% | 1.015x |

The mixed and zero book-31 gains are clear. The maximum-escape case is smaller;
its full dispersion is retained in the summary. Untouched controls move too:
book-13 mixed input uses more cycles while the bit-reader control uses fewer.
The incremental effect of keeping the walker inlined is measured separately
in that same window:

| Input | Before cycles | After cycles | Reduction | CPU throughput |
| --- | ---: | ---: | ---: | ---: |
| Book 31, mixed input | 18,458.19 | 16,933.33 | 8.3% | 1.090x |
| Book 31, zero pairs | 11,396.00 | 11,328.83 | 0.6% | 1.006x |
| Book 1, nonzero pairs | 14,449.91 | 13,932.10 | 3.6% | 1.037x |

Mixed input exercises residual tree walks and improves by 8.3%. The four-bit
zero-pair code is resolved entirely by the prefix lookup, so it did not call
the walker; its 0.6% change is near a tie. These cases support removing the
extra call rather than adding a general inlining policy.

The final immutable table elements total **6,236 bytes**, versus **5,610 bytes**
at baseline: a net increase of **626 bytes**. There is no lazy initialization,
heap allocation or decoder-state increase. The wire-format CSV remains
byte-identical. The generator reproduces the Rust tables, CSV and metadata
byte for byte. Independent checks compare every pair word, every escape/count1
prefix slot and every signed-quadruple record with the numeric fixtures.
[Final table audit, byte counts, commands and hashes](2026-10-28-mp3-escape-tables.json).
The saved benchmark executable grows from 574,464 to 576,000 bytes, including
linked probe/production code and linker padding; this is not an application
binary-size measurement.

fixtures. Minimum/maximum, median absolute deviation and nanoseconds are
retained in the summaries. These are coverage/performance fixtures, not a
representative listening workload.

## Rejected variants

An arithmetic sign-batching variant used runtime popcount and four dependent
sign reconstruction steps. A three-run rotating screen increased mixed
count1-A from 6,445.40 to 11,829.95 cycles and table B from 5,537.11 to
9,763.58. A prefix trial on top of it did not recover the baseline. This
variant was replaced by the compact signed-output records.
[Screen observations](2026-10-28-mp3-quad-screen.tsv),
[screen manifests and summary](2026-10-28-mp3-quad-screen.json).

A broad five-bit pair lookup helped long symbols, but one-bit zero pairs in
books 1/7/13/23 became approximately 12-15% slower. A separate head-bit table
recovered those zeros, but book-1 nonzero pairs became 20.9% slower than the
count1-only stage, and much of the book-31 gain disappeared. These broader
variants were rejected in favor of the shared escape-family lookup. Their
source/binary hashes and seven-run observations remain in the first comparison;
the [broader trial's mapping audit](2026-10-28-mp3-huffman-tables.json) is retained
separately from the final audit.

## Code generation

The standalone quad function changes from 213 static instructions at baseline
to 158 with signed-output records, then 192 with the count1-A lookup. Its stack
reservation changes from 32 to 32 to 40 bytes. The lookup adds straight-line
decoding instructions while eliminating repeated loop iterations.

The initial focused pair lookup caused the compiler to emit a separate
56-instruction tree walker. A private `inline(always)` annotation restores the
baseline's inlining of that small hot loop. The separate helper disappears,
the pair function remains at 292 static instructions, and its stack reservation
returns from 104 to 96 bytes. These counts cover the extracted standalone
bodies, excluding other helpers, and are not retired-instruction measurements.
The source/binary CPU comparisons remain the performance evidence.
