# Native encoding

The encoder is independent of the decoder and of external codecs. The public
`FrameEncoder` creates one raw FLAC frame. `Encoder<W>` wraps it in native FLAC,
accepting planar and interleaved right-aligned signed i32 PCM without clipping
or float conversion. All depths 4..32 and channel counts 1..8 are supported.

## Compression and integer precision

Each channel is evaluated as constant, verbatim, fixed prediction, and (when
enabled) LPC. Stereo compares independent, left-side, side-right and mid-side
costs. Common trailing zero bits are removed through FLAC's wasted-bit field.
Verbatim provides a bounded fallback, including signals whose residuals cannot
be represented in FLAC's legal signed 31-bit-magnitude range.

LPC proposals use Hann-windowed autocorrelation and Levinson recursion, then
quantize coefficients to at most 15 bits and a nonnegative shift. Floating point
affects only predictor proposals. Every residual is computed and range checked
with i64 integer arithmetic. A failed proposal is discarded. Consequently, the
compressed bytes may vary across math-library implementations; decoded PCM does
not. The decoder does not share the encoder's predictor or residual routines.

Both Rice parameter methods and escape partitions (including zero-width escapes)
are considered. Parameter selection finds the exact minimum of the discrete Rice
length, and candidate partition orders are compared using their total bit count.
Subframe bit counts include warmups, coefficients, wasted bits and parameter
overhead. A debug invariant checks the prediction against the written bit count.

| Level | Maximum fixed order | Maximum LPC order | Maximum partition order |
| --- | ---: | ---: | ---: |
| 0 | 2 | 0 | 0 |
| 1 | 4 | 0 | 2 |
| 2 | 4 | 0 | 3 |
| 3 | 4 | 6 | 3 |
| 4 | 4 | 8 | 4 |
| 5 | 4 | 8 | 5 |
| 6 | 4 | 10 | 6 |
| 7 | 4 | 12 | 6 |
| 8 | 4 | 32 | 8 |

Levels describe this implementation's search effort, not libFLAC-compatible
presets. `max_lpc_order` and `max_partition_order` override these limits through
32 and 15 respectively. Order/partition choices are constrained by the actual
block length. Some settings produce valid non-subset FLAC (for example, LPC order
32 at 44.1 kHz). No streamable-subset conformance is promised for every option.

`block_size` is 16..65535 for streaming. A final block may be shorter, down to one
sample. Raw `FrameEncoder` calls accept 1..65535 samples and caller-supplied frame
or sample numbers. The caller must make raw frame sequences and their STREAMINFO
bounds consistent. `variable_block_size` writes sample numbering. Streaming
currently emits nominally equal blocks even when that flag is enabled; raw frame
calls can choose each block length independently.

## Streaming, metadata and failures

`Encoder::new` writes STREAMINFO immediately. `with_metadata` preserves supplied
standard/application/unknown blocks and optionally reserves SEEKTABLE slots.
STREAMINFO and SEEKTABLE are generated by the encoder; callers supply other
metadata as `MetadataBlock` values. The normal metadata parser validates all
blocks and singleton constraints before anything is written.

- `write_planar` accepts equal-length channel slices.
- `write_interleaved` accepts any whole number of interchannel samples.
- Input boundaries do not affect frame boundaries or output bytes.
- `finish_seekable` flushes the last block, installs sample count, digest and
  min/max frame sizes, writes seek points, then restores the writer position.
  Nonzero initial writer offsets are supported. Existing trailing data is not
  truncated by this generic Write+Seek API.
- `finish` works with any Write. STREAMINFO retains unknown count/digest and
  reserved seek slots remain placeholders, as permitted for live output. The
  returned `EncodedStream` contains final statistics, MD5 and seek points.
- Seek points are progressively thinned to fit the reserved count. Offsets are
  relative to the first audio frame; points stay sorted and cover progressively
  longer streams without retaining one entry per frame.
- All input/codec/write failures are terminal for a streaming encoder. Finishing
  after a failed write is rejected; a partially written output is not advertised
  as complete. Raw FrameEncoder errors leave it reusable.

Scratch PCM, residual, parameter, bitwriter and frame buffers are reused. Their
allocation behavior and memory consumption still need the planned benchmark
instrumentation. No claim of zero steady-state allocations is made yet.

## Validation evidence, 2026-10-27

Six local encoder tests cover every depth and channel count; levels 0, 5 and 8
across that matrix; all nine levels across five signal families; every stereo
selection; LPC selection; sample and frame numbering; tiny/maximum blocks;
sample rates through 1048575 Hz (and zero for non-audio); metadata; empty streams;
I/O failures; all important streaming chunk sizes; and seek-table thinning.
Planar and interleaved output is checked byte for byte, including a nonzero writer
origin. Debug builds also exercise the subframe cost invariant.

The external matrix contains 696 generated cases: 29 bit depths, 8 channel
counts, and 3 levels. Each has 1025 samples/channel, 256-sample nominal blocks,
and one of constant, alternating extrema, ramp, deterministic noise or a mixture
of sinusoids. Level 8 uses variable sample numbering. Every case must pass:

1. Native encode -> libFLAC decode -> exact original PCM, including digest checks.
2. libFLAC encode -> native decode -> exact original PCM and verified digest.
3. Native encode -> Symphonia raw-frame decode -> exact original PCM, except the
   two pinned reference regressions below.

libFLAC 1.5.0 passes all 696 cases in both directions. Symphonia 0.6.1 matches 694
and reproduces its known 32-bit stereo limitation in two cases. These exact first
differences are asserted, not tolerated in native PCM:

| Configuration | First Symphonia difference |
| --- | --- |
| 32 bits, stereo, level 0 | channel 1, sample 0: expected 999999, actual 1 |
| 32 bits, stereo, level 5 | channel 0, sample 0: expected 0, actual 999999 |

The checked report [validation/encoding-matrix.tsv](validation/encoding-matrix.tsv)
contains full-file and audio-frame byte counts for both encoders, as well as
exact-comparison outcomes. Metadata sizes differ (native reserves four seek
points; libFLAC writes its default comments), so use frame bytes to compare
compression separately from container overhead. These tiny synthetic cases are
correctness vectors; they do not establish representative music compression or
throughput. Full-file speed/ratio comparisons remain part of the performance
milestone.

Build the pinned C oracle as documented in [COVERAGE.md](COVERAGE.md), then run:

```powershell
$env:DEADLIB_FLAC_ORACLE = (Resolve-Path target/deadlib-flac-reference/oracle-build/Release/deadlib_flac_oracle.exe).Path
$env:DEADLIB_FLAC_GENERATED = "$pwd/target/deadlib-flac-reference/generated"
$env:DEADLIB_FLAC_ENCODING_REPORT = "$pwd/crates/deadlib-audio/decode/flac/validation/encoding-matrix.tsv"
cargo test -p deadlib-audio-decode-flac --target-dir target/deadlib-flac --release --test encoding -- --include-ignored
```

The test-only oracle's `encode INPUT.i32le OUTPUT.flac RATE CHANNELS BITS LEVEL
BLOCK` mode feeds exact signed i32 PCM through libFLAC's public encoder API with
verification enabled and subset restrictions disabled. It is never a production
dependency. Generation is deterministic and reuses three scratch files under the
chosen output directory rather than checking hundreds of files into the repo.
