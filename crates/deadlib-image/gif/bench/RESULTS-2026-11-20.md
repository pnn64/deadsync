# GIF decoder optimizations: 2026-11-20

Three improvements are retained: transfer the completed header, transfer the
compositor canvas into owned output, and bulk-fill long uniform rows after
fixed-size equality checks. Production still forbids unsafe code and depends
only on the local `deadlib-image` crate. DeadSync loader integration is separate.

All 35 repository GIF assets beat the reference paths in every final comparison.
The complete corpus contains **176 files, 1,958 frames, and 85,970,999 frame
pixels**: 35 assets, 13 upstream samples, and 128 deterministic generated inputs.
No input is excluded. Native compatibility mode (`strict: false`) includes the
three legacy samples omitted by the November 17 strict-mode campaign.

## Before/after improvements

### Move the retained header

The whole-file decoder accumulates blocks directly and moves its completed
header into the returned GIF. This removes the extra global-palette clone and
the intermediate `Option<Gif>` state and unwraps.

| Metric, all 176 retained decodes | Before | After |
| --- | ---: | ---: |
| Allocation calls | 3,376 | 3,201 |
| Requested bytes | 90,083,734 | 90,052,156 |
| Native retained cycle ratio | 1.0000 | 0.9720 |
| Unchanged gif retained control | 1.0000 | 0.9958 |

The change removes 175 allocations and 31,578 requested bytes, with 2.8% fewer
retained-decoding cycles in its isolated stage. Evidence:
[baseline timing](results/2026-11-20/baseline.tsv),
[step3 timing](results/2026-11-20/step3.tsv), and their
[before](results/2026-11-20/baseline-alloc.tsv) /
[after](results/2026-11-20/step3-alloc.tsv) allocation tables.

### Move the displayed canvas into owned output

`Compositor::into_image` transfers its `Vec<[u8; 4]>` through safe
`into_flattened`, replacing an allocation and full canvas copy. It returns the
currently displayed pixels; pending disposal belongs before the next graphic
and is not applied by this conversion.

The step6 same-executable `native-first/native-copy-first` comparison has a
**0.8485 cycle ratio**, or **15.2% fewer cycles**, across all 176 files. It removes exactly
one allocation per input: **176 calls and 130,995,924 requested bytes** across
the corpus. The independent ownership test checks zero allocation/reallocation,
the original buffer pointer, exact pixels, valid RGBA8 dimensions, and pending
background disposal.

Both benchmark paths return identical owned images and include destruction.
This ownership improvement is separate from the native/reference comparison.
[Step6 timing](results/2026-11-20/step6-first.tsv),
[allocations](results/2026-11-20/step6-first-alloc.tsv), and
[all losses](results/2026-11-20/step6-first-summary.json) are retained.

The final retained executable measures an ownership cycle ratio of
**0.82135**,
with 174 wins and two timing losses. The allocation saving holds on every input;
both timing exceptions remain in the table below.

### Bulk-fill long uniform rows

For visible rows of at least 32 pixels, the compositor compares 16-byte arrays
and the remaining tail, then fills a uniform row with one palette color or
skips a wholly transparent row. Mixed and shorter rows use the existing pixel
loop. This removes repeated palette lookups and stores on uniform rows without
adding heap allocations, cached palettes, unsafe code, or CPU-specific APIs.

The focused 80 ms stage9 comparison lowered cycles on the 16 large flat inputs
to **0.86344** of the original row path, while the unchanged gif asset control
was **0.98241**: a 13.7% measured native reduction. The final retained first-image
comparison against step6 over those same 16 files is **1.09888**
native, with a **1.24990** gif control. Both raw costs increased in
that later run; the native/reference ratio improves by
**12.08%**. This is a reference-normalized
comparison, not a reduction in those later raw native cycle counts.

A subsequent matched 100 ms confirmation used nine inputs, including three
large flat files. Those three measured **0.90887**
native after/before cycles with a **1.02168**
gif control. This confirms the benefit on the retained source. The three
selected small assets measured **1.02245**
native with **1.00204** gif: a small
remaining cost versus native's original row path, while still beating the
reference. The optimization is a measured workload tradeoff.

The initial implementation scanned short rows as well. An independent review
of file descriptors found all 34 lighting assets use rows of 4, 7, or 23 pixels.
The 4-pixel and 7-pixel groups regressed 4.99% and 1.72% versus step3 after
normalizing against gif's compositor. Requiring 32 visible pixels avoids that
scan. Across all 35 assets, the final guard changes native RGBA cycles by
**1.05100** relative to the ungated broad run; the gif RGBA control
changes by **1.10611**. Native indexed control modes also drifted,
so the entire ratio change cannot be attributed to the guard. The first-image
asset comparison versus the ungated run is **0.97530** native
with **1.00008** gif. This shows the short-row refinement's
benefit more directly, without claiming a win over every earlier native stage.

Evidence: [focused baseline](results/2026-11-20/step6-rows-first.tsv),
[fixed-size scan](results/2026-11-20/step9-rows-first.tsv),
[ungated broad run](results/2026-11-20/final.tsv), and
[retained guarded run](results/2026-11-20/final2.tsv).
The targeted confirmation is retained as
[before](results/2026-11-20/step6-confirm-first.tsv),
[after](results/2026-11-20/final2-confirm-first.tsv), and

## Method, scope, and reproduction

Host: **Intel(R) Xeon(R) CPU E5-2696 v4 @ 2.20GHz**, Windows-11-10.0.26100-SP0; **rustc 1.100.0 (0ef1bc386 2026-11-09)**. Release builds use
optimization level 3, LTO, one codegen unit, and the repository's static-CRT
target flags. Reference versions are gif 0.14.2, gif-dispose 6.0.0, and image
0.25.10. The timing thread is pinned to logical CPU 0 and records Windows
`QueryThreadCycleTime`. Each result is a median of five batches; mode order
rotates between files. Allocation measurement uses separate calibrated builds.

| Measurement | Minimum duration per batch |
| --- | ---: |
| Initial baseline and step1 complete-animation runs | 40 ms |
| Steps2–5 complete-animation candidates | 20 ms |
| Step6 ownership run | 40 ms |
| Step6/step7 focused metadata runs | 100 ms |
| Step6/step8/step9/step10 focused row runs | 80 ms |
| Ungated broad animation and first-image runs (`final.*`) | 40 ms |
| Retained guarded animation and first-image runs (`final2.*`) | 20 ms |
| Targeted retained confirmation and near-parity repeats | 100 ms |

None of this task's builds or tests ran alongside timing passes; unrelated host
work was not stopped. Control modes and repeated measurements expose run-to-run drift.
These measurements establish performance on this Windows x64 host, not other
CPU or OS combinations.

Before timing, the complete-animation harness verifies indexed pixels,
palettes, rectangles, controls, every composited canvas, and delays against the
reference decoders. Native streaming recycles frame storage. The retained
reference moves owned frames rather than cloning them; streaming gif uses
`read_into_buffer`. Native retains extension metadata that the reference frame
loops do not retain in the same representation. Reusable RGBA modes expose a
borrowed canvas, whereas image returns an owned frame for each animation step.

The first-image harness returns identical owned RGBA canvases from all four
paths. It times the in-memory, color-key-disabled asset-loader decode/expand
core, excluding file I/O, signature/buffering work, and two allocation-limit
guards. It intentionally stops after the first image and omits the trailer.
`image-first` uses the animation iterator's first frame. The reference palette
loop carries a scoped Clippy expectation so it stays identical to production.
Output allocation and destruction are included; input reading is outside timing.

[README.md](README.md) contains the build and reproduction commands. Set
`GIF_BENCH_MS` to the duration for the desired stage and use `--compatibility`
for this complete corpus. Input bytes and SHA256 values are in
[inputs.json](results/2026-11-20/inputs.json).

## Validation and provenance

- Retained source: **38 tests passed**, zero failed; one optional external giflib
  oracle test was ignored because its external helper was not configured.
- Both final full-corpus timing runs and their allocation runs cover all 176
  files without exclusions and verify complete output parity before measuring.
- Regression coverage includes clipped uniform/mixed/transparent rows around
  31/32/33 pixels, ownership without copying, metadata fragmentation and exact
  budgets, LZW overflow prefixes, and interlace scratch reuse after tall frames.
- Formatting passed for changed Rust files. Strict Clippy passed for all package
  targets and all benchmark targets/features. Production dependency audit shows
  only local `deadlib-image`.
- Independent source and benchmark reviews found no correctness blocker.
  No new production unsafe code or external production dependency was introduced.
- All 176 input hashes still match the initial corpus; final source and executable
  identities are recorded in [final2 identity](results/2026-11-20/final2-identity.json)

the archived bytes across Git checkouts. PowerShell's `NativeCommandError`
